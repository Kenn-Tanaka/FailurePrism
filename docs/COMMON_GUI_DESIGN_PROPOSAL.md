# FailurePrism 共通 GUI デザイン仕様書（案）

| 項目 | 内容 |
| --- | --- |
| 文書版 | 0.1（提案） |
| 作成日 | 2026-10-21 |
| 対象 | FailurePrism Shell、TPDD-Editor、VTA-Editor、および今後追加するツール |
| 目的 | ツールごとに異なる編集画面を保ちながら、ファイル操作・LLM接続・通信状況・出力を一貫して扱える共通 GUI を定義する。 |

> 本書は将来の GUI 方針案であり、現行実装の確定仕様ではない。現状の挙動・制約は [共通要件](REQUIREMENTS.md) を正とする。

## 1. 設計方針

FailurePrism は「編集を止めず、必要なときだけ AI を使えるローカル優先のワークベンチ」とする。全ツールで次の原則を共有する。

1. **作業を最優先する。** 中央の編集キャンバスを最も広く使い、接続やログは編集を妨げない位置に置く。
2. **ファイル操作を探させない。** 読込・保存・画像保存・他形式への出力を、共通の「ファイル」メニューへまとめる。
3. **AI の状態を隠さない。** 接続状態、接続先、処理中、失敗理由、通信履歴を役割ごとに分けて提示する。
4. **オフラインでも機能低下を局所化する。** Gateway 未接続時も、編集・読込・保存・画像出力は利用できる。AI 操作だけを無効化し、理由と復旧手段を示す。
5. **安全な既定値を使う。** トークン・認証ヘッダ・入力データ中の機微情報を通信ログと保存ファイルへ出さない。外部送信の有無を利用者が判断できるようにする。
6. **共通操作は同じ名称・アイコン・ショートカットにする。** ツールを切り替えても、保存・書出し・設定の位置と意味を変えない。

## 2. 情報アーキテクチャ

### 2.1 グローバル領域とツール領域の責務

| 領域 | 責務 | 置くもの | 置かないもの |
| --- | --- | --- | --- |
| Shell（全画面共通） | ワークベンチ全体の移動、共通設定、接続の可視化 | 製品名、ツールタブ、ファイル、接続ステータス、設定入口 | 編集対象固有の詳細設定 |
| ツール・ヘッダー | 現在のプロジェクトと基本操作 | プロジェクト名、未保存表示、Undo/Redo、ツール固有の主要操作 | Gateway の資格情報 |
| 作業領域 | ユーザーの主作業 | 図、表、キャンバス、詳細ペイン、AI 提案 | 恒常的に展開された通信ログ |
| 下部ユーティリティ | 観測・通知・補助情報 | LLM通信ログ、検証結果、ジョブ進捗、ステータス | 接続設定フォーム |

### 2.2 推奨ナビゲーション

上部バーを次の順に構成する。

```text
[FailurePrism] [メニュー] [TPDD] [VTA] … | [ファイル ▾] [編集 ▾] [表示 ▾] | [● 接続中  LM Studio Remote (Tailscale) ⚙]
```

- 左側は製品・ツールの移動であり、常に表示する。
- 中央は現在のツールに対する共通メニュー。狭い画面では「…」へ折りたたむ。
- 右側は LLM 接続の要約である。クリックで接続の詳細ポップオーバー、歯車で設定パネルを開く。
- 現行の接続再確認は、状態表示のポップオーバー内にある「再確認」へ移す。状態バッジ本体を再診断専用ボタンにしない。

## 3. 画面レイアウト

### 3.1 標準デスクトップ配置

```text
┌─────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│ FailurePrism | メニュー | TPDD | VTA          ファイル  編集  表示          ● 接続中 接続先名 ⚙       │
├─────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ プロジェクト名  ●未保存   新規  Undo/Redo  [ツール固有の主操作]                                           │
├───────────────┬───────────────────────────────────────────────────────────────┬─────────────────────────┤
│ コンテキスト  │                                                               │ 詳細／AI支援            │
│ ・構造/一覧   │                         主作業キャンバス                        │ ・選択項目              │
│ ・検索        │                                                               │ ・提案                  │
│               │                                                               │ ・適用                  │
├───────────────┴───────────────────────────────────────────────────────────────┴─────────────────────────┤
│ 通信ログ（折りたたみ可能）                              直近: 完了  2.1 s  ·  エラー 0  ·  [ログを開く] │
└─────────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

- 主作業領域は最小でも横幅の 55% を確保する。左右ペインはリサイズ・折りたたみ可能とする。
- 下部の通信ログは初期状態を **1行の要約バー** にし、展開時のみ 200〜320 px を使用する。画面高を恒常的に消費しない。
- 各ツールはこの骨格を守り、固有の詳細ペイン・キャンバス・主要アクションを差し替える。

### 3.2 小さい画面・狭幅時

- 1024 px 未満では左または右ペインをドロワー化する。
- 768 px 未満ではメニューをオーバーフローメニューへ収容し、通信ログはボトムシートで開く。
- 接続表示は `● 接続中` を優先し、接続先名は省略記号で切り詰める。完全な名称・URL はポップオーバーで確認できる。
- 重要な操作はアイコン単独にせず、狭幅でもツールチップとアクセシブルな名前を持たせる。

## 4. ファイルメニュー（共通）

ファイル入出力はツール固有の左ペインから取り除き、上部の **ファイル** に集約する。ツールが非対応の項目は表示しないか、理由を添えて無効化する。

| グループ | 項目 | 共通動作 | 例 |
| --- | --- | --- | --- |
| 作成 | 新規プロジェクト | 未保存変更があれば確認後、新規状態を作る | TPDD: プリセット選択、VTA: 空/サンプル選択 |
| 入力 | 開く… | 対応するプロジェクト形式をファイル選択して検証・読込する | `.tpdd.json`、VTA JSON |
| 入力 | インポート… | プロジェクト形式以外を取り込む。読込後の影響範囲を示す | CSV、画像、テンプレート等（ツール対応時のみ） |
| 保存 | 保存 | 現在のプロジェクトをダウンロードする。既存ファイルを直接上書きする意味にはしない | `Ctrl/Cmd+S` |
| 保存 | 名前を付けて保存… | 保存名・形式を指定する。ブラウザ環境ではダウンロード名の指定として扱う | `Ctrl/Cmd+Shift+S` |
| 出力 | 画像として保存… | 表示範囲または選択範囲を PNG/SVG 等で出力する | PNG、SVG |
| 出力 | エクスポート… | 目的別の形式とオプションを選ぶモーダルを開く | PDF、JSON、CSV、Markdown、報告書形式等 |
| 補助 | 自動保存と復元… | ブラウザ内の復元候補を確認・削除する | IndexedDB の下書き |

### 4.1 「画像として保存」と「エクスポート」の区別

利用者に形式選択を強制しすぎないため、用途で入口を分ける。

- **画像として保存**: 資料へ貼るための視覚成果物。既定は PNG、必要時に SVG を選べる。
- **エクスポート**: 再利用・連携のための構造化成果物。形式ごとのオプション（範囲、メタデータ、レイアウト、添付物）を選ぶ。
- **保存**: FailurePrism で再編集するためのプロジェクト形式。成果物出力と混同しない。

出力モーダルには、各形式について「用途」「含まれる情報」「再編集可否」「推奨先」を短く表示する。例: `SVG — Office等へ貼り付けるベクター図。再編集用プロジェクトではありません。`

### 4.2 未保存変更の扱い

次の操作では、未保存状態を判定して確認ダイアログを出す: 新規、開く、インポート、ツール切替での破棄、ブラウザ離脱。

- 主ボタンは `保存して続行`、副ボタンは `保存せず続行`、安全側の初期フォーカスは `キャンセル` とする。
- 自動保存がある場合も、ダウンロード済みプロジェクトが更新済みとは表示しない。
- 保存・出力の成功は、形式・ファイル名・時刻をトーストで通知する。

## 5. LLM 接続ステータスと設定

### 5.1 右上の接続表示

接続バッジは「現在使えるか」と「どこへ接続するか」を一目で示す。

| 状態 | 表示例 | 色・補助表現 | 操作 |
| --- | --- | --- | --- |
| 接続中 | `● 接続中　LM Studio Remote (Tailscale)` | 緑 + `接続中` の文字 | クリックで詳細、歯車で設定 |
| 確認中 | `◌ 接続確認中　LM Studio Remote…` | 青/中立色 + スピナー | 詳細で中断・再確認 |
| 注意 | `! 制限あり　LM Studio Remote…` | 黄 + 原因の要約 | 詳細で診断 |
| 未接続 | `○ 未接続　既定 Gateway` | 灰 + `未接続` の文字 | 詳細で再確認、歯車で設定 |
| エラー | `! 接続エラー　LM Studio Remote…` | 赤 + `接続エラー` の文字 | 詳細で原因・再試行 |

色覚差・高コントラスト環境を考慮し、色だけで状態を伝えない。接続先はプロファイル表示名を優先し、未命名時のみホスト名または `/v1` を表示する。認証トークン、完全な API URL のクエリ、資格情報はバッジ・ツールチップ・ログに表示しない。

### 5.2 状態ポップオーバー

バッジ本体を押すと、設定を変えずに状況を確認できるポップオーバーを開く。

```text
LLM 接続
● 接続中  / 直近確認 19:34:12 / 応答 84 ms
接続先: LM Studio Remote (Tailscale)
経路: FailurePrism → /v1 → LLM-Gateway → LM Studio
モデル: qwen2.5-coder:14b
[再確認]  [通信ログを開く]                       [設定を開く]
```

詳細表示では、接続プロファイル、経路、最終確認時刻、遅延、選択モデル、失敗時の安全な診断情報を示す。接続テストを手動実行できるが、通常のクリックだけで頻繁な再診断を発生させない。

### 5.3 LLM 設定パネル

歯車は右サイドシート（狭幅ではモーダル）で設定を開く。編集画面を離れず、変更は明示的に保存・適用する。

| セクション | 項目 |
| --- | --- |
| 接続プロファイル | プロファイル選択、表示名、既定化、追加・複製・削除 |
| 接続先 | 経由接続 (`/v1`) / 直接接続、ベースURL、接続テスト |
| モデル | モデル選択・検索、お気に入り、ツール別の既定モデル |
| 通信 | タイムアウト、ストリーミング、JSONモード、必要時のクライアントトークン |
| プライバシー | 外部送信の注意、ログ記録レベル、機微情報マスク方針 |
| 診断 | ヘルス結果、モデル一覧取得結果、設定のエクスポート/インポート（資格情報を除外） |

- Gateway 自体のプロバイダ資格情報管理は、既存の Maintenance Tool を正とする。FailurePrism 内の設定画面はエディタの接続プロファイル・モデル・通信方針を扱い、プロバイダ API キーを重複管理しない。
- クライアントトークンを扱う場合はメモリ保持を既定とし、永続化する場合は用途・保存先・削除方法を明示して別途承認する。
- `適用` 後に接続テストを促す。失敗しても編集状態を失わず、直前の有効設定へ戻せる。

## 6. LLM 通信ログ

空く左下の「LLM設定」領域は、**LLM通信ログ**へ転用する。接続設定は全体共通のため右上の歯車へ集約し、ツール内に重複させない。

### 6.1 表示内容

ログ1件は最小表示で次を示す。

| 項目 | 例 | 備考 |
| --- | --- | --- |
| 時刻・状態 | `19:34:12　完了` | 成功、キャンセル、警告、失敗をアイコンと文字で示す |
| 操作 | `TPDD: 展開案を生成` | ツールと機能を人が読める名称で示す |
| 接続先・モデル | `LM Studio Remote / qwen2.5-coder:14b` | 接続先の表示名を使用 |
| 所要時間・量 | `2.1 s · 入力 1,240 · 出力 386` | 取得できる場合だけ表示 |
| 詳細 | `要求概要 / 応答概要 / エラー詳細` | 初期状態は折りたたむ |

ログは新しい順に表示し、`すべて / 実行中 / 成功 / 警告 / エラー` のフィルタ、検索、コピー、クリア、テキスト出力を備える。処理中のログはキャンセル操作を持つ。

### 6.2 プライバシーと保持

- API キー、Bearer token、Cookie、Authorization ヘッダは常に伏せ字にする。
- プロンプト・応答本文は **既定で要約のみ** を表示し、詳細本文は利用者が明示的に展開したときだけ表示する。
- ログの保存範囲は `このセッションのみ` を既定とする。永続ログは明示的な有効化、保持期間、削除ボタンを必要とする。
- ログのエクスポート前に、本文・ファイル名・識別子・機微情報の含有可能性を確認する注意を出す。
- 保存対象・マスク規則は、後続のセキュリティ設計で確定するまで「ベストエフォートの診断情報」として扱い、監査証跡を名乗らない。

## 7. 操作・表示の共通規約

### 7.1 コマンドと言葉

| 意図 | 表示名 | アイコン例 | ショートカット |
| --- | --- | --- | --- |
| プロジェクトを作る | 新規プロジェクト | FilePlus | `Ctrl/Cmd+N` |
| プロジェクトを読む | 開く… | FolderOpen | `Ctrl/Cmd+O` |
| プロジェクトを保存する | 保存 | Save | `Ctrl/Cmd+S` |
| 別名・形式で保存する | 名前を付けて保存… | SaveAs | `Ctrl/Cmd+Shift+S` |
| 視覚成果物を出す | 画像として保存… | ImageDown | なし |
| 連携データを出す | エクスポート… | FileOutput | なし |
| LLM を設定する | LLM接続設定 | Settings | なし |
| 接続状態を調べる | 接続を再確認 | RefreshCw | なし |
| ログを見る | 通信ログ | ScrollText | なし |

`ダウンロード`、`保存`、`出力`、`エクスポート`を混在させない。UI上の主要名称は上表に統一し、必要に応じて補助文でブラウザのダウンロード動作を説明する。

### 7.2 フィードバック

- 非同期処理は、開始直後に対象操作の近くへ進捗を出し、完了・失敗・キャンセルをトーストと通信ログへ残す。
- エラー文は「何が起きたか」「編集に影響があるか」「次にできること」を順に記載する。
- AI失敗時は、キャンバス編集や保存をブロックしない。再試行・設定を開く・ログを見る導線を出す。
- 破壊的操作（新規化、読込による置換、ログクリア、プロファイル削除）は確認を要する。

### 7.3 アクセシビリティ

- すべてのアイコンボタンに名称、ツールチップ、キーボード操作を提供する。
- 状態は色・文字・形（アイコン）で二重化する。
- フォーカス順は、上部バー → ツールヘッダー → 主作業 → サイドペイン → 下部ログとする。
- モーダル/サイドシート表示中はフォーカスを閉じ込め、Escで安全に閉じる。未保存設定がある場合は確認する。

## 8. ツールへの適用例

| 要素 | TPDD-Editor | VTA-Editor | 共通化の判断 |
| --- | --- | --- | --- |
| 保存 | `.tpdd.json` | VTAプロジェクトJSON | ファイルメニューで入口を統一、拡張子と検証は各ツールが担当 |
| 画像保存 | SVG / PNG | SVG（将来PNG等を追加可能） | 出力モーダルの共通骨格を使用 |
| AI操作 | 展開案、代替案、レビュー | 抽出、分析、レビュー等 | 実行内容はツール固有、通信履歴・接続表示は共通 |
| 自動保存 | IndexedDB復元候補 | 下書き復元候補 | 「自動保存と復元…」から各ツールの状態へ遷移 |
| 左下領域 | LLM通信ログ | LLM通信ログ | 旧LLM設定パネルを置き換える |

## 9. 実装上の境界

この提案は Shell が共通コンポーネントを提供し、ツールが能力を宣言する形を推奨する。

```text
Shell
 ├─ GlobalMenu: ファイル / 編集 / 表示 / 接続
 ├─ ConnectionStatus: 表示・詳細・設定入口
 ├─ ConnectionSettingsSheet: 接続プロファイル・診断
 ├─ ExportDialog: 形式選択の共通骨格
 ├─ CommunicationLogPanel: 絞込・マスク・コピー
 └─ Tool Adapter: 各ツールの開く・保存・出力・自動保存能力を接続
```

各ツールは少なくとも `open`、`save`、`exportFormats`、`hasUnsavedChanges`、`restoreDrafts`、`reportLLMEvent` を Shell に提供する。未対応の能力は宣言しない。これにより、Shell 側に TPDD/VTA 固有の形式や業務ルールを埋め込まない。

導入は次の優先順を推奨する。

1. 右上の接続表示を「状態 + 接続先 + 歯車」に変更し、設定の責務をここへ集約する。
2. 左下のLLM設定を通信ログの折りたたみパネルへ置換する。
3. 共通ファイルメニューと、保存/画像保存/エクスポートの共通モーダル枠を導入する。
4. 各ツールの既存操作を共通コマンドへ段階的に接続する。
5. ログの永続化・詳細本文の取り扱いは、プライバシー方針と併せて別途確定する。

## 10. 受入観点（案）

| ID | 確認事項 |
| --- | --- |
| GUI-C01 | 右上で接続状態と接続先名を、色だけに依存せず確認できる。 |
| GUI-C02 | 歯車から接続プロファイル、モデル、タイムアウト、接続テストを開ける。設定は各ツールで重複表示されない。 |
| GUI-C03 | Gateway未接続でも新規・読込・保存・画像保存・対応するエクスポートを利用できる。 |
| GUI-C04 | ファイルメニューから新規、開く、保存、画像として保存、エクスポート、復元を一貫した名称で実行できる。 |
| GUI-C05 | 通信ログで操作、結果、接続先、モデル、所要時間、エラーを確認でき、トークン等の秘密情報を表示しない。 |
| GUI-C06 | 未保存変更を失う可能性がある操作では、保存・破棄・キャンセルを選べる。 |
| GUI-C07 | 主作業キャンバスが常時優先され、ログ・設定・左右ペインを折りたたみまたはリサイズできる。 |
| GUI-C08 | キーボード操作、フォーカス、文字ラベルにより、アイコンや色だけに依存せず共通操作を完了できる。 |

## 11. 未決定事項

- エクスポート対象として共通必須にする形式（PNG/SVG以外）の範囲。
- LLM通信ログの永続化可否、保持期間、詳細本文の扱い。
- 接続プロファイルをブラウザ内へ保存するか、Gateway設定と連動させるか。
- プロジェクト間のデータ変換・インポートを共通ファイルメニューで扱うか。
- 最低対応画面幅、アクセシビリティ目標水準、翻訳方針。
