# 思考展開図エディタ (TPDD) クイックスタートガイド

本ガイドは、「思考展開図エディタ (Thinking Process Development Diagram Editor - TPDD)」を初めて利用する方向けに、アプリケーションの起動から基本的な図の作成、AI支援によるアイデア展開、ファイルの保存およびSVGエクスポートまでの一連の流れをステップ・バイ・ステップで解説します。

## 1. 起動と準備 (1分)

### 1.1 一括起動
1. 本パッケージのルートにある **`start-all.bat`** をダブルクリックします。
2. 2つの黒いコマンド画面（「LLM Gateway (8765)」および「TPDD Web Server (3000)」）が自動的に立ち上がります。
3. 既定のブラウザ（Chrome / Edge / Firefox）が起動し、以下のURLが自動で開きます：
   - **エディタUI**: `http://127.0.0.1:3000`
   - **LLM Gateway**: `http://127.0.0.1:8765/v1`

> [!TIP]
> **ローカルLLMの事前起動**:  
> AI支援機能（展開案・代替案・レビュー）を利用する場合は、LM Studio や Ollama などのローカル推論ツールをあらかじめ起動し、モデル（例: `lmstudio/default`, `gemma-2-27b`, `gpt-4o` 等）をロードしておいてください。

## 2. 画面構成の基本 (1分)

エディタ画面は以下の5つの主要領域で構成されています：

```
+-----------------------------------------------------------------------------------+
|  [上部ツールバー] 新規作成 / 読込 / 保存 / 出力 / 設計体系 / 整列 / Undo / Redo          |
+-------------------+-------------------------------------------+-------------------+
|                   |                                           |                   |
|  [左ペイン]       |  [中央 SVG キャンバス]                    |  [右ペイン]       |
|                   |                                           |                   |
|  - プロジェクト名 |  - プリセットまたはユーザー定義の抽象度列 |  - ノード詳細     |
|  - 図一覧ツリー   |  - ノードカード (矩形)                    |    (ラベル/種別/  |
|  - パンくず階層   |  - 接続線・エッジ (ベジェ矢印)            |     状態/説明/etc)|
|  - LLM設定 /      |  - ズーム / パン / グリッド               |  - AI支援パネル   |
|    モデル探索     |                                           |    (展開案/代替案/|
|                   |                                           |     図レビュー)   |
+-------------------+-------------------------------------------+-------------------+
|  [下部ステータスバー] 自動保存状態 (IndexedDB) / ノード・エッジ件数 / ズーム率 / Revision  |
+-----------------------------------------------------------------------------------+
```

## 3. サンプル図を読み込んでみる (2分)

まずは同梱のサンプルファイルを読み込んで、完成した展開図のイメージを確認しましょう。

1. 画面上部ツールバーの **「ファイル読込」** ボタンをクリックします。
2. ファイル選択ダイアログで、`samples/sample-project.tpdd.json` を選択します。
3. **「スマートオフィス環境制御システム」** の展開図が読み込まれます：
   - 左から「要求」「機能」「機構」「構造」の4列にノードが整列配置されています。
4. **サブ図への移動（階層化）**:
   - 「機能」列にあるノード **「エリア別最適空調制御」** を**ダブルクリック**してください。
   - 子階層のサブ図（温湿度フィードバック制御）へ画面が切り替わります。
5. **親の図へ戻る**:
   - キャンバス左上のパンくずリストにある **「ルート展開図」** をクリックすると、元の全体図に戻ります。

## 4. 新規プロジェクトを作成して図を描く (3分)

### 4.1 新規プロジェクトの作成
1. 上部ツールバーの **「新規作成」** ボタンをクリックします。
2. 用途に合うプリセットを選びます。
   - **機械設計**: 要求・機能・機構・構造を中心とする初期体系
   - **ソフトウェア設計**: 要求・責務・論理設計・実装要素を中心とする初期体系
   - **電子回路設計**: 仕様・電気的機能・回路方式・部品を中心とする初期体系
   - **カスタム**: 最小限の定義から独自の体系を作成
3. **「この設定で作成」** を押すと、選択した定義を持つ既定名称の白紙Projectが表示されます。新規作成モーダルでは名称や説明は入力しません。
4. Project名や説明を変える場合は、作成後に左ペインのProject名をクリックしてProject設定を開きます。プリセットは出発点であり、名称を固定しません。

### 4.2 設計体系を確認する

ツールバーの **「設計体系」** を開き、次の違いを確認します。

- **種別**: ノードが何を表すかを示します。名前、AI向け説明、表示パレットを追加・編集できます。
- **抽象度列**: 設計上の段階・観点と図上の配置先を示します。名前、AI向け説明、左から右の順序を追加・編集できます。
- 種別と列は独立しています。同名である必要はなく、たとえば「インターフェース」種別を複数の列で使えます。
- AIを使う場合は、独自名称だけでなく「この種別・列に何を書くか」という説明も入力すると分類と提案が安定します。

### 4.3 ノードの追加
1. 上部ツールバーの **「ノード追加」** ボタンをクリックします。
2. キャンバス中央に新しいノード（下書き状態）が生成されます。
3. **ノードの編集**:
   - ノードをクリックして選択すると、右ペインに「ノード詳細」が表示されます。
   - **ラベル**: 「オフィス温度の均一化」などと入力します（ノード上の直接ダブルクリックでも編集可能）。
   - **種別**: 現在のProjectで定義された「内容の種別」を選択します。
   - **抽象度列**: 設計段階・観点として配置したい列を選択します。
4. **位置の移動**:
   - ノードをマウスでドラッグすると、自由な位置へ移動できます。

### 4.4 エッジ（接続線）の作成
1. 始点としたいノードにマウスカーソルを合わせると、ノード右端に小さな「接続ポイント（○）」が現れます。
2. その接続ポイントを**ドラッグ**し、接続先ノードの上で**ドロップ**します。
3. 矢印付きのエッジが生成されます。
4. エッジをクリックすると、右ペインでエッジの種別（`分解`、`依存`、`制約`、`参考`）やラベルを変更できます。

### 4.5 キャンバスの操作
- **ズーム**: マウスホイールの回転（25% 〜 400%）
- **パン（視点移動）**: キャンバスの何もない部分をドラッグ（またはスペースキー＋ドラッグ）
- **全体表示**: ツールバーの虫眼鏡アイコンをクリックすると、全ノードが収まる倍率に自動調整されます。
- **自動整列**: ツールバーの **「自動整列」** を押すと、各列のノードが重ならないよう一瞬できれいに整頓されます。

## 5. AI支援で思考を展開する (3分)

LLMと連携して、選択したノードのブレークダウン案や代替案を生成してみましょう。

### 5.1 対象ノードの選択
1. キャンバス上で、アイデアを深めたいノード（例: 要求「オフィス温度の均一化」）をクリックして選択します。

### 5.2 AI支援パネルの操作
1. 右ペインの **「AI支援」** タブを開きます。
2. **タスク選択**:
   - **展開案**: フォーカスノードを具体化する下位候補を生成。既定の配置先はフォーカスの次の列です（最終列では同じ列）。
   - **代替案**: フォーカスノードを置き換える同階層の候補を生成。既定の配置先はフォーカスと同じ列です。
   - **図レビュー**: 現在の図全体を分析し、抜け漏れや矛盾を指摘。
3. **配置先列**:
   - 1回の実行で生成する候補の配置先を1列選びます。既定値をそのまま使うことも、実行前に変更することもできます。
   - 選んだ列の名前と用途説明がLLMへ送られ、全候補はその列へ配置されます。
4. **指示入力（任意）**:
   - 「省エネルギーに配慮した方式を中心に提案してください」などの要望を自由に入力できます。
5. **生成ボタンをクリック**:
   - Gateway経由でLLMへ推論リクエストが送信されます。
   - ストリーミングが有効な場合、受信文字数がリアルタイムにカウントアップ表示されます。

### 5.3 提案候補の確認と安全な採用
1. 推論が完了すると、AIから提示された候補ノード一覧が表示されます。
2. 候補ごとに内容、種別、**提案理由 (Rationale)** を確認します。配置先は候補別ではなく、生成前に選んだ共有の1列です。
3. LLMが返した種別を解決できない候補には種別選択欄が表示されます。採用したい候補の種別を手動で選びます。
4. 採用したいノードのチェックボックスをオンにします（すべて採用、または必要なものだけを個別選択）。
5. **「選択した候補を採用」** ボタンをクリックします。
6. 選択した候補が指定列へ入り、接続線はアプリが安全に生成します。

> [!NOTE]
> **安全機能（Undo対応 & アプリ管理の接続線）**:
> - 採用操作は1回の履歴として記録されるため、上部ツールバーの **「元に戻す (Undo)」** または `Ctrl+Z` を1回押すだけで、採用前の状態に完全に復元できます。
> - LLMには候補ID、列ID、接続線を生成させません。展開案には「分解」、代替案には「参考（代替）」の線をアプリがフォーカスノードから生成します。
> - 候補間の依存・制約が説明や確認事項に書かれている場合は、採用後に必要な線を追加してください。

## 6. 保存とSVG出力 (1分)

### 6.1 プロジェクトのJSON保存 (`.tpdd.json`)
- 上部ツールバーの **「JSON保存」** をクリックします。
- プロジェクト全体（設計体系、すべての図、ノード、エッジ、階層構造、来歴データ）がschemaVersion 2の `.tpdd.json` としてダウンロードされます。
- 次回はこのファイルを「ファイル読込」から開くだけで、いつでも編集を再開できます。

> [!WARNING]
> 開発版ではデータモデルを簡潔に保つため、schemaVersion 1以前や旧formatとの互換読込・自動移行を提供しません。必要な旧データは旧版アプリ側で退避してください。

> [!TIP]
> **自動保存（IndexedDB）**:
> 編集内容は1秒ごとにブラウザ内部のIndexedDBへ自動保存されています。万が一ブラウザを誤って閉じたりPCが再起動した場合でも、次回起動時に「未保存の復元候補」ダイアログが表示され、直前の状態から復旧できます。

### 6.2 標準SVGエクスポート (Office連携)
- 上部ツールバーの **「SVG出力」** をクリックします。
- 現在表示されている図がスタンドアロンの `.svg` ファイルとして出力されます。
- 本エディタのSVGは `<foreignObject>` を一切使わない純粋な標準ベクター形式で出力されるため、**Microsoft Word や PowerPoint にドラッグ＆ドロップするだけで、文字化けやレイアウト崩れなく高品位に貼り付け・拡大縮小**できます。

## 7. 次のステップ

基本操作に慣れたら、より高度な機能もぜひご活用ください：

- **設計体系のカスタマイズ**: 「設計体系」から、組織固有の種別と列（例: 「ユーザーストーリー」「ドメイン責務」「回路ブロック」「検証項目」）を追加し、それぞれの意味を説明できます。
- **モデル探索モーダル**: 左ペイン下部の「モデル探索」から、Gatewayに接続されている全モデルの検索やお気に入り登録ができます。
- **ショートカットキーの活用**: `Delete`（削除）、`Ctrl+Z`（Undo）、`Ctrl+Y`（Redo）などのキーボードショートカットで軽快に操作できます。

詳しい機能仕様や設定項目の解説は、[リファレンスマニュアル (REFERENCE_MANUAL.md)](./REFERENCE_MANUAL.md) をご覧ください。


### Gateway接続先

TPDD-Editorの既定接続先は `/v1` です。VTA-Editorと同じWebサーバー中継を利用します。独自のloopback接続先はGateway設定から指定できます。
