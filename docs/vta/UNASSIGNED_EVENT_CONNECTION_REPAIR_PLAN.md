## 2. 解決方針

「表示カード間の線の提案」と「未割当・不足イベントを含む連鎖の修復」を区別し、利用者が問題に適した処理へ進めるようにする。線の提案だけを繰り返して完了したように見せない。

既存proposeChainRepairは全analysis、原文、診断を受け取り、追加イベント・割当・関係を差分提案できる。この実装を拡張する。二つ目の独立した割当修復エンジンは作らない。

LLMは出来事の粒度、主体の対応、工程依存、根拠の種類を判断する。アプリはID・参照・候補依存・整合性・採用状態を検証する。結線・通電という語に対する固定ペア接続や、システム部門への固定割当は実装しない。

## 3. 修復の流れ

1. 全イベント、未割当、帰結の未表示、既存カード・関係・利用者の非表示／削除指定を診断する。
2. 未割当がある場合、「通電試験での過電圧印加：主体未割当のため接続提案の対象外」など、対象外のID・理由を表示する。
3. 利用者が「主体・不足イベントも含めて点検」を選ぶと既存の連鎖点検を開く。自動通信・自動適用はしない。
4. LLMへ全文と全イベントを渡し、独立した通常作業の不足、主体割当、工程依存を優先点検させる。既存イベントIDを再利用する。
5. 候補を「イベント」「主体割当」「接続」「要確認」に分け、対応する原文と根拠種別を表示する。
6. 利用者が割当・必要イベントと、それを参照する関係を選択して一括適用する。適用後に未割当・未表示帰結・未接続を再診断する。

## 4. 入力台帳と参照の修正

共通入力ビルダーを用意し、接続専用提案と連鎖点検で原文参照の作り方を共有する。提案入力は簡潔なTSV主体とし、全文analysisのJSONを何度も再掲しない。

- 全イベントにはID、時刻、見出し、内容、記録区分、実際の原文参照、割当／表示状態を含める。
- 接続専用提案では未割当イベントも文脈として渡すが、採用可能な端点は既存表示カードに限定することを明記する。端点が不足する関係は対象イベントID付き要確認とし、割当修復への導線を出す。
- 連鎖点検では全イベントに対する割当追加と、それを参照する関係追加を許可する。追加できない既存割当の付替え・分割は要確認へ返す。
- 原文表はref、実参照イベントID、用途（direct/context）、本文を分ける。隣接段落を補助送信しただけなら、隣接イベントのIDを実参照として転記しない。
- 実参照イベントIDは全events.sourceRefsから逆引きする。今回p7の実参照はE7,E8、E6ではない。
- 選択範囲外・未割当・利用者の非表示・手動削除は別の状態として扱う。全件入力を理由に非表示や削除を解除しない。

## 5. LLMの意味判断規則

### 5.1 通常作業と帰結を分離する

「通電試験時に過電圧が印加され破損した」のような記述から、実施された試験、状態変化、損失を区別して点検する。既存E7が過電圧、E8が破損なら、欠けた試験実施だけを追加候補にする。E7・E8の改名による置換・削除はしない。独立した試験実施が既にあれば既存IDを再利用する。

「予定」「仮定」「もし実施したら」を実施済みに変換しない。試験時という表現から実施を読み取る場合も、原文の該当範囲と理由を提示する。主体や実施時刻は別に判断し、同時に推測して埋めない。

### 5.2 主体・割当と責任を分離する

原文明示、文脈で支持される対応、特定不能を区別する。「試験前確認をした部門」と「通電試験を実施した主体」を無条件に同一視しない。責任・過失の主体をイベントの実施主体の代わりに要求しない。機器が客体であるという理由で機器レーンを復活させない。

文脈からの割当は候補として提示し、原文で明示された割当と同じ確度で自動確定しない。主体を特定できない場合の選択肢は以下とする。

- 未割当のまま保持し、未解決事項を表示する。
- 利用者が既存主体を選んで割り当てる。利用者による判断であることを記録する。
- 利用者の明示操作で、例えば「通電試験の実施主体（未特定）」という仮レーンを追加し、対象イベントだけを割り当てる。

仮レーンは実在組織を創作するものではなく未特定状態を可視化する。entityに任意のresolution=unresolvedを持たせ、通常レーンと表示を区別する。仮レーンがある限り主体特定を完了扱いにしない。未特定という理由だけで全イベントを同じ仮レーンへ自動集約しない。既存の通常主体にはこの属性を要求しない。

### 5.3 工程依存と時間順・因果を区別する

- 前後に書かれている、時刻が近い、同じ事例というだけではdependencyにしない。
- 同じ対象に対する先行作業の結果・完了・状態を後続作業が使用することを、明示的記述または原文全体の具体的な文脈で支持できる場合、dependency候補とする。非隣接でもよい。
- 文脈による候補にはsource-contextという根拠区分と、参照段落・判断理由を必須にする。一般的な工学知識だけで接続しない。
- 文脈による工程依存を、原文に明記された因果関係・専門家評価に変換しない。source-assessmentとも区別する。
- beforeは引き続き時間順の制約として扱い、一律に線へ変換しない。
- 結線から試験前確認への線を固定しない。実際の後工程となる試験実施への依存を別に点検する。試験実施→過電圧→破損の関係も、時間順と物理的影響を区別して提案する。

この規則は通常抽出、接続専用提案、連鎖点検の実効プロンプトで共有する。

## 6. データ契約・検証・採用

- 割当へ任意のevidenceBasis、sourceRefs、reason、generationを保存できるようにする。原文明示recorded、文脈source-context、利用者userを区別する。イベント本体のrecordKindとは独立させる。
- 関係のevidenceBasisにもsource-contextを追加し、保存読込・レポート・SVG説明欄で保持・表示する。文脈候補を原文明示としてレポートしない。
- 連鎖差分の割当追加を7列（ID、イベント、主体、役割、原文参照、根拠区分、理由）へ拡張する。関係追加は現行12列の根拠区分を拡張し、列を増やさない。
- 接続専用提案は根拠区分列を追加する。各形式の契約版を明記し、生成・部分修復・検証・カスタムプロンプトの実行時契約を揃える。古い列形式を推測して読み替えない。
- 保存データへの追加項目は任意属性とし、現行5.0の正常データは追加属性なしでも読む。旧形式の変換機能は作らない。
- 関係候補が新規イベント・割当へ依存する場合、その候補IDをUIへ表示する。「必要な候補も選択」で依存候補を選べるが、初期選択・自動適用はしない。必要候補を外した場合は適用を停止する。
- 別イベント・別主体、原文参照、循環、削除済み関係、重複を引き続き検証する。LLMが同じ未割当イベントを別IDで追加して問題を迂回しないよう、既存IDの再利用を明示する。
- 適用は一回のcommitとし、Undo/Redoで一括復元する。処理中に図・入力・プロジェクトが変わった場合は古い候補の適用を拒否する。
- 構造検証の成功と意味上の不足を分ける。台帳が形式上正常でも未割当・仮レーン・未表示帰結があれば、その件数と未解決理由を表示する。

## 8. 受入試験

1. 提供ログと同じE7・E8未割当データを読み、帰結は存在するがカード化されていないと診断する。初回抽出をやり直さず修復へ進める。
2. 接続専用入力でp7をE6の根拠として誤表示しない。E7・E8を文脈として含め、カードがない理由を明記する。
3. 疑似LLMが既存E7/E8への割当と工程依存を返した場合、両方選択すれば描画・保存・読込が成功する。割当を選ばなければ接続だけは適用できない。
4. 不足する試験実施だけを追加し、既存の過電圧・破損を保持する。既存の試験実施があれば重複追加を要求しない。
5. 明示された試験主体は通常割当、文脈候補は根拠付き確認、特定不能は要確認として扱う。システム部門へ自動固定しない。
6. 同じ対象への工程依存をsource-context候補として提示・採用できる。時系列だけ・別対象・一般知識だけの例は接続しない。
7. 予定・仮定の試験を実施済みにしない。仮レーンを自動生成せず、利用者の作成後も未解決状態を維持する。
8. 利用者の非表示・削除・BREAK・配置を維持する。仮レーンの表示名だけで実在主体へ確定しない。
9. 現行5.0の保存読込、source-contextの保存・SVG・レポート、一括Undo/Redo、キャンセル・古い応答拒否を確認する。
10. 実LLM評価では今回のサンプルと、主体明示／主体不明／別対象の反例を使う。疑似応答による構造試験の成功を実モデルの意味判断品質の証明にしない。

成功条件は「無条件に全カードへ線が出る」ではなく、「根拠と割当を確認すれば結線から通電側へ接続でき、不明な場合にもどこが未解決かを利用者が確認・修復できる」である。

## 9. 計画の自己点検

- 未割当を入力へ含めるだけでは、主体必須の端点契約が満たせない。割当候補と接続の同時採用まで実装対象とした。
- p7の誤ラベルだけを直しても、割当と工程依存は生成されない。入力修正と意味判断・UIを分けた。
- 既存の連鎖点検は既に全文を受け取る。全文送信機能の追加を解決として重複実装しない。
- 文脈から工程を読めることと、特定部門の実施・責任を断定できることは異なる。割当不明を許容し、仮レーンは利用者の明示操作に限定した。
- 通電試験という通常作業の追加はLLMの提案とし、文字列ルールによる自動分割・結線ではない。
- 新しい根拠区分をUIだけに置くと保存・レポートで消えるため、データ契約・出力・試験まで同じ段階で変更する。
- 機器レーンや同一イベント複製による強制接続を解決策に含めない。元の帰結IDも保持する。
