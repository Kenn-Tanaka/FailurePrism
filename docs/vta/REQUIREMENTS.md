# VTA-Editor 要件定義書

文書版1.0／2026-10-18／実装基準 `493c052`。共通の境界・記載ルール・非機能要件は[共通要件](../REQUIREMENTS.md)を適用する。本書は現行実装からの再構成であり、受入済みの宣言ではない。

ノード位置編集拡張の実装内容と受入状況は[実装仕様書](NODE_POSITION_EDITING_SPEC.md)を参照。

## 1. 目的・対象業務

事故・不具合の経緯を、主体別レーンと時系列を持つバリエーションツリーとして可視化する。利用者が通常事象と変動事象を整理し、要因の排除・因果関係の遮断を対策として設定し、改善後フローと分析レポートを生成するまでを支援する。

想定利用者は事故調査担当者、安全・品質担当者、分析結果のレビュー担当者。AIの抽出・提案は人が確認する分析材料である。定量的な事故確率計算、対策の有効性証明、安全認証、事実認定は対象外である。

## 2. 業務フロー・ユースケース

| UC | フロー | 正常終了 | 代替・例外 |
| --- | --- | --- | --- |
| VT-UC01 | 経緯入力または文書読込→AI抽出→図の確認 | レーン・事象・関係線を持つ編集可能な図を得る | 不正応答・通信失敗を通知し、再実行や手動編集を可能にする |
| VT-UC02 | ノード・線の追加/修正→配置調整→補足記入 | 原資料に対応した分析図を作成する | 削除時は接続線を除き、履歴対象操作はUndoできる |
| VT-UC03 | 排除・遮断を手動設定、またはAI提案を選択適用 | 対策状態が図とデータへ反映される | 不明なノード・線への提案は適用しない |
| VT-UC04 | 対策反映後に再生成→改善後フロー・分析レポート確認 | 2種類のMarkdown結果を得る | 中止や失敗を通知。生成中/生成後の編集による陳腐化を区別する |
| VT-UC05 | JSON保存→読込、または起動時の下書き復元 | 経緯・図・生成済みレポートを再利用する | 不正データは拒否または補正通知。復元対象外項目は自動復元を保証しない |
| VT-UC06 | 出力設定→SVGダウンロード、結果のコピー | 図・補足または文章を他資料へ利用できる | JSONによる作業保存とは別の成果物として扱う |

初期表示にはサンプルを用意する。サンプル切替、JSON読込、AI抽出による図の置換では、未保存状態に応じた確認を行う。空の新規Projectを作成するTPDDと同一の業務フローとは定義しない。

## 3. 入力・取込要件

| ID | 要件 | 根拠 | 受入条件 |
| --- | --- | --- | --- |
| VT-I01 | 経緯テキストを直接入力・編集し、用意されたサンプルを選択できること | V1、V2 | 入力した経緯を抽出要求と保存データへ使用する |
| VT-I02 | ファイル選択とドラッグ＆ドロップで文書を取り込めること | V2、V3 | 対応形式を読み、ファイル名・種類・サイズ・抽出文字数またはエラーを表示する |
| VT-I03 | TXT/LOG/MD/MARKDOWNをテキストとして読み、UTF-8、Shift_JISの順に復号を試みること | V3 | 両文字コードの日本語資料を取り込める |
| VT-I04 | DOCX本文、XLSX/XLSの各シート、PDFのテキスト層から経緯用テキストを得ること | V3 | 表計算は見出し付きMarkdown表となり、複数シートを識別できる。PDFはページごとの文字を抽出する |
| VT-I05 | `.json`入力をVTA Project読込へ振り分けること | V1、V2 | JSONを単なる経緯本文として扱わず、形式5.0とイベント参照を検証する。旧形式と単独VTASchemaは拒否する |

DOCXの図表配置・書式やPDFの元レイアウトを完全再現する機能ではない。PDFの画像だけのページはOCR対象外。表計算はシート当たり見出しを除く最大1,500行、PDFは先頭250ページを処理し、省略を知らせる。入力ファイルは形式によらず最大25MiBであり、上限超過は解析前に拒否する。

非表示化はカードの描画属性であり、ノードの削除・排除対策とは別に扱う。既存の矢印方向、双方向指定、ラベル、分類、BREAKを保持し、接続先ではない線の交差には接続点を付けない。非表示ノードが連続する場合や分岐・合流でも接続関係を変更しない。線のないノードは独立した点として残す。

通常表示のカード上には「図上では接続点として表示」を明示し、カード編集画面からも指定できるようにする。右側説明欄の各ノードにも同じ切替を置き、図を縮小した場合や見出しのみの表示でも操作できるようにする。

接続点のクリックでも右側の該当説明へ移動する。説明欄の「図上表示」は点への移動とし、カードの再表示は「カードを再表示」または編集画面での明示操作によって行う。接続点は両表示モードでドラッグでき、端子からの接続追加は無効とする。

同一レーンの新規接続は時系列線、レーン間接続は一方向線として作成する。方向変更と関係分類は別属性である。レーン・時刻に関わる変更では再配置が発生し、通常の文章修正では手動位置を保持する。

自動生成された図は、LLMが出力した台帳のイベント順に従う。独立イベントは別IDとし、時刻不明等を理由にアプリが統合しない。共有カード表で指定されたグループだけを表示上まとめ、時刻差・前後関係と矛盾する指定は修復する。カード整理後、同一レーンの隣接カードを接続し、飛び越し線を作らない。保存済み・手動編集済みの接続修正は明示操作で行う。

レーン間の線が循環して上下関係を同時に満たせない場合、自動配置は同一レーンの時系列順を優先する。循環を作るレーン間の線は表示・保存したまま、その線を上下順の制約から外す。

レーン間エッジはノード左右の側面端子を使用し、送信端子を受信端子より上側に配置する。過去の事象（下方）から後の事象（上方）へ向かう基本フローで、不要な交差を抑える。レーン内エッジの上下端子と接続方法は変更しない。

### 操作と履歴範囲

| 操作 | 割当て・範囲 |
| --- | --- |
| JSON保存 / 読込 / SVG出力画面 | CtrlまたはCmd+S / O / E |
| Undo / Redo | CtrlまたはCmd+Z / Y、CtrlまたはCmd+Shift+Z。入力欄ではテキスト編集を優先 |
| ズーム | 0.1～2.5倍。ミニマップ・全体表示を利用 |
| Undo対象 | VTASchemaに対する履歴登録済み編集。経緯本文、接続設定、生成結果の完全な巻戻しではない |
| 補足本文の更新 | 変更・保存対象だが、独立したUndo履歴を積まない更新経路がある |
| 図全体置換/読込 | 履歴をリセットする。直前データの内部退避は通常Undoと別の仕組み |

非表示ツールへのキーボード操作は共通要件COM-03に従う。

| 線 | source、target、任意のis_break/direction/label/category |
| 線の方向 | sequential / unidirectional / bidirectional |

| カスタム補足 | id、任意のnodeId、title、content |
| 再生成結果 | idealFlow、analysisReport、generatedAt、任意のsourceHash |
| AI対策提案 | summary、排除候補、遮断候補、generatedAt。各候補の参照・理由・推奨行動を保持 |
| 採用済みイベント関係 | source/targetイベント・主体、種類、根拠参照、リソース・実施・受領属性。提案ID・LLM理由・採用理由・由来を保持 |
| 未適用の接続候補 | 現在の作業画面だけに保持し、プロジェクト保存には含めない |

| ID | 要件 | 根拠 | 受入条件 |
| --- | --- | --- | --- |
| VT-D01 | 外部JSONとAI抽出結果を検証・正規化してから図にすること | V3、V6 | 基本構造を欠く入力を拒否し、修正可能な項目を補完して警告を出す |
| VT-D02 | ノードID重複、レーン不足、線の参照切れ・自己接続・重複を補正すること | V3 | IDの再採番、レーン補完、不正線除去の結果と警告を確認できる |

VTAはTPDDの厳格なProjectスキーマと異なり、欠損属性の補完や不正要素の除外を行う。最大ノード数・線数・文章長について明示的な一律上限は確認できない。無制限の性能保証を意味しない。

## 6. 保存・復旧・出力要件

| ID | 要件 | 根拠 | 受入条件 |
| --- | --- | --- | --- |
| VT-P01 | 経緯・図・再生成結果をProject JSONとしてダウンロードできること | V1、V2 | version、savedAt、scenarioText、vtaData、regenerationResult、selectedModelを出力する |
| VT-P02 | 完全Projectと単独VTASchemaを読み込めること | V1、V3 | 完全Projectでは経緯・図・レポートを復元し、単独スキーマでは図を置換して既存の経緯を保持する |
| VT-P03 | 読込時に実行中AIを中止し、作業単位を切り替えること | V1 | 旧要求の遅延応答が読み込んだ図を上書きしない |
| VT-P04 | 下書きをブラウザ内へ保存し、起動時に候補の復元・破棄を選べること | V1、V2 | 非空図を含む下書きを提示し、復元時は経緯・図・レポートを読み戻す |
| VT-P05 | ファイル名・空レーン・補足・コンパクト化・上部見出しの有無を指定してSVG出力できること | V4、V5、追加要件 | 指定オプションに対応した単一SVGを生成し、日本語・XML特殊文字を保持する。上部見出しを含む場合は白背景と濃色文字で描き、省略する場合は見出し領域の余白も詰める |
| VT-P06 | 改善後フローと分析レポートをMarkdown表示し、結果をコピーできること | V2 | 各タブを切り替えて閲覧し、対応する文章をコピーできる |

Project出力のversionは`5.0`。Gateway URL/Token、timeout、操作ログ、Undo履歴、未適用のAI対策提案はProject出力対象ではない。型定義にあるprojectNameやmeasuresProposalも、現行export処理の出力項目には含まれない。

下書きはlocalStorageの`vta_draft_autosave`という単一スロットに、savedAt、scenarioText、vtaData、regenerationResultを保存する。同一Originの別タブと保存先を共有するため、複数Projectの版管理ではない。復元候補はノードがある図に限られ、保存領域の容量不足・利用不可では保存を保証できない。

SVG設定の初期値は空レーンを含めない、補足と上部見出しを含める。コンパクト化の初期値は現在の表示モードに従う。VTAの直接出力機能としてPNG・PDF・DOCXを定義しない。

SVGの右側補足欄には、ノードの`description`（内容）と`supplementary_note`（背景要因などの補足説明）をそれぞれ表示する。見出しのみの図を出力する場合も、補足欄を含めればノード内容を参照できる。補足欄を除外した出力では両方の文章が含まれないことを出力画面で知らせる。

カードの非表示属性をSVGにも適用し、接続点と全接続線を出力する。補足欄には非表示ノードも残し、図上が接続点であることを明示する。保存した表示指定は形式5.0のプロジェクトと下書きから復元する。AI抽出データの表示指定は採用しない。非表示ノードも分析対象に含め、表示属性だけの変更では分析結果を古いと判定しない。

### レーン表示とカード整理の追加要件（2026-10-28）

- 正規データの全カード・主体・関与を保持し、表示除外と実削除を区別する。
- レーンは自動／表示／非表示を指定できる。表示は除外カードも復元し、手動追加の空レーンを残す。非表示はユーザーの指定を優先する。
- 自動整理は初期生成と明示適用時に実行する。通常の編集では必要なカードを復元するだけとし、新たな除外を行わない。
- レーン管理で表示数／割当数、除外理由、図上にないイベント・線の数を確認できる。関係の端点は別主体に付け替えない。
- レーンの表示設定と全カードの配置・補足・接続点・対策を保存し、下書き復元・Undo/Redoに対応する。SVGと説明欄も可視範囲に従う。
- 分析とレポートには非表示対象を含む正規データを使う。表示変更だけではレポートを古いと扱わない。
- 背景・除外・要確認の要旨・理由・参照原文を確認でき、選択した記録の原文から再抽出できる。イベントがない場合は0件を明示する。

イベントと関係は原文を直接参照し、変動判定もTSV形式とする。意味の判断はLLMが担当し、参照先の存在は意味の正しさの保証とはしない。現行実装の詳細と自己点検は[TSV台帳仕様](TEXT_LEDGER_SPEC.md)を参照。


2026-10-29 時刻不明イベントの配置更新：analysisを持つ図では、レーン内のsequence_orderを共通の時間として扱わず、イベントIDを基準に全レーンの順位を決める。共通イベント・共有カードは同じ順位とし、明示されたbefore、impact、transferと接続の前後関係を優先する。関係がない候補はsourceOrder（入力記述順）で並べる。循環する追加制約と同一イベント間の線は時間差に変換しない。カード・接続点の中心を同じ高さへ揃え、発生時刻の文字列は補わない。保存済みの手動配置を持つ図はBT自動整列で再配置する。
# 作業依存と生成方式の拡張（2026-10-29）

- 異なる主体のイベント間で、原文が前提作業と依存作業の関係を示す場合、非隣接でも作業依存を抽出・提案できること。隣接するだけでは接続の根拠としない。
- 隣接は対象2レーンの全イベントから判定し、第三レーンの無関係なイベント、カードの座標・列順に左右されないこと。非隣接依存を提案しても、同一レーンの隣接時系列線を飛越し線で置き換えないこと。
- 作業依存は前提から依存先への矢印、「作業依存」ラベル、一点鎖線で示すこと。リソース移動や作業実施の有無とは区別すること。
- AI接続提案は原文と理由を利用者が確認して採用し、既存の手動線・BREAK・削除指定を尊重すること。保存・Undo/Redo・SVG・レポートへ反映すること。
- 将来の生成方式を共通分析データへ接続する入口を備えること。現行方式は全文正規化・TSV台帳方式とし、来歴を保存すること。方式不明または未搭載方式の既存データでも、共通データが有効なら表示・編集できること。

主体と客体の区別：操作・試験の対象や被制御対象・被害物であるだけの機器はレーンへ登録せず、イベント本文に保持する。独立した自動検知・制御・通信等を担う機器は、原文の根拠があれば主体にできる。破損等のイベントは除外せず、対応する操作・試験主体が判明していればそこへ割り当て、不明なら未割当・要確認とする。既存図の主体を機器という種類だけで自動削除しない。


## デバッグ記録（2026-10-29）

- 利用者がデバッグ詳細記録をON/OFFでき、初期値はOFFとする。記録中は常時見えるVTAヘッダーにも状態と停止操作を設ける。
- 原文・プロンプト・LLM応答、検証、図への反映状態を追跡し、記録済み内容をJSON保存・消去できる。通常ログとは独立させる。
- メモリ内で容量を制限し、省略・破棄件数を表示する。画面再読み込みでOFF・消去とし、自動送信・自動保存は行わない。認証ヘッダーを収集せず、Gatewayトークンを詳細通信記録から除去する。


## 未割当イベントと工程依存の確認（2026-10-29）

- 未割当イベントと図上未表示の帰結を、抽出失敗・利用者による非表示とは区別して表示する。接続専用提案から、既存の全文連鎖点検へ進めること。
- 全イベント・原文の実参照を点検入力に含め、隣接補助文脈に近隣イベントの参照IDを誤付与しない。
- LLMが原文全体の具体的文脈で支持される工程依存・主体割当をsource-context候補として提案でき、利用者が原文と理由を確認して必要候補ごと採用できること。時系列だけ・一般知識だけの接続は作らない。
- 主体・責任主体を混同せず、不明な主体を固定部門へ自動割当しない。仮レーン作成は利用者の明示操作だけとし、未解決状態を保持する。
- 既存のイベント・帰結ID、手動非表示・削除・BREAK・位置を保持し、一括適用・Undo/Redo・保存読込・SVG説明・レポート・デバッグ記録に対応する。既存5.0データへ新属性を要求せず、旧形式変換は追加しない。


## 正規化時の主体推定・簡素表示（2026-10-29 更新）

- 主体の明記がない場合、同じ全文正規化のLLM処理で文脈から実施主体を推定し、イベントとレーンに割り当てる。直前イベントの主体を決定論的にコピーしない。
- 推定した割当には「主体は推定」とだけ表示する。主体推定の根拠・理由・原文明示との詳細区分は要求せず、推定だけを理由とする追加の承認やLLM照会は設けない。
- 推定表示は割当単位で保存・読込・確認・説明欄・SVG・レポートへ引き継ぐ。主体のみ推定でも、記録されたイベントのrecordKindをassessmentへ変更しない。
- 文脈からも推定できない場合は未割当を維持する。既存5.0データの推定フラグは任意とし、保存済みの旧割当根拠情報は読めるが新しい詳細表示は行わない。関係自体の根拠規則は維持する。


## 事実遵守・正規化監査記録・主観表現点検・主体粒度反復評価（2026-10-31 追加）

- **事実遵守と推定補完の禁止（factuality-1）**: 表記ゆれの統一と明らかな誤字・脱字の補正を除き、原文に書かれていない事実・心理・動機・意図・時刻・因果関係・未記載手順を推定で補完しない。主語省略時の主体推定は同一段落または直前段落の明示された主語の引き継ぎに限定し、引き継げない場合は未割当（`-`）を保持する。
- **原文不変性とプロンプト機械無害化**: `VTASource`（`text` および `paragraphs`）は不変とし、NFKC変換や文字置換を行わない。LLM入力文字列の生成時のみ、制御文字の空白化、台帳予約見出し（`[主体]`〜`[完了]`）の全角括弧化、三連バッククォートの無害化を行う。
- **表記統一・誤字脱字補正の記録**: 正規化台帳の任意セクション `[表記]` にて、原文に実在する表記（`from`）から統一後表記（`to`）への変換を段落参照・理由付きで記録し、原文に存在しない語句の記録は警告のうえ除外する。
- **主観的・責任追及表現の生成禁止と原文検知記録**: AI生成文に評価・過失認定語（「誤って」「誤認」「不注意」「怠った」等）を含めない。生成文に検知された場合は行単位の言い換え修復を試み、残存時も処理を停止せず記録する。原文自体に含まれる主観表現はアプリ側の辞書走査（`scanSource`）とLLMの `[表現]` セクションの双方で非停止にて検知・統合し、供述（`claim`）の引用保持または評価語除去の扱いを `normalizationAudit.subjectiveNotices` に記録する。
- **仮変動判定と確定判定の分離**: 正規化時の `[仮判定]` は `event.preliminary` に参考値として保持し、イベント自体の `classification` は `unclassified` のままとする。確認画面で「仮判定を採用」ボタンによる手動採用、または確定後の「変動要因を判定」への参考入力として利用できる。
- **主体粒度・ツリー複雑度の反復評価（`refined-chain`）**: 仮判定された変動要因から帰結への到達性（C3）および人間の認知負荷（C5：レーン数・カード数・最大接続次数・交差数・最長経路長）を含む評価関数 $S$ とハードゲート（G1〜G4）により、最大反復回数内で主体分割・統合・関係修正を反復評価し、最良スナップショットと反復履歴（`normalizationAudit.iterations`）を保持する。
- **監査記録の表示・出力とハッシュ除外**: 確認画面の折りたたみパネル（`NormalizationAuditPanel`）および右側の根拠注記（`evidenceNotes`）で記録を確認でき、Markdown表およびJSON形式でコピー・レポート付録出力できる。`normalizationAudit` および `event.preliminary` は `computeVTADataHash` の算出対象から除外し、監査記録の有無だけで既存レポートを古いと判定しない。
- **LLM入力トークンの効率化（token-optimization-1）**: 事実性遵守・推測禁止・TSV構文・抽出品質を一切損なわず、LLM入力トークンを抑制する。プロンプト内の過渡的メタ言及除去、JSONペイロードのミニファイ（20〜30%削減）、接続提案候補ペアの上限適正化（500件・スコープ優先）、台帳修復時の契約プロンプト二重送信解消とIDカタログ最適化を行う。
