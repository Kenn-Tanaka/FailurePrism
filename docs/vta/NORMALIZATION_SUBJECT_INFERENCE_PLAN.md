# 正規化時の主体推定 実装計画・自己レビュー

2026-10-29。利用者の最新指定を優先する。主体を全文の文脈からLLMが推定して正規化時に割り当て、「主体は推定」とだけ表示する。推定根拠や原文明示との詳細区分は新たに要求しない。

## 実装計画

1. 正規化プロンプトの「明記なしなら未割当」「割当は後段の候補へ回す」という制約を改める。LLMが工程・対象・前後文脈から実施主体を推定する。直前イベントの主体をプログラムでコピーしない。試験前確認→通電試験の例を含め、単なる客体の機器レーンや事故責任の推定とは分ける。
2. 正規化のイベント表は既存7列を維持する。主体と役割セルに `A2:actor:inferred` の任意修飾子を追加する。通常の `A2:actor` も読める。推定理由表・追加LLM照会・推定ごとの承認は追加しない。
3. 割当データに任意のinferred真偽値を追加し、型・保存検証・正規化修復で保持する。推定フラグは割当単位で、イベント本文のrecordKindや主体エンティティ全体の属性にしない。
4. 確認画面と右側説明欄に「主体は推定」を表示する。SVG説明欄とレポートにも同じ表示を引き継ぐ。主体割当の従来の根拠区分・理由・参照の詳細表示はやめる。関係自体の根拠表示は変更しない。
5. 後段の連鎖点検も同じ簡素な割当に揃える。割当追加は6列（ID、イベント、主体、役割、原文参照、推定表示inferred/-）、契約chain-delta-3とし、割当理由・区分は生成させない。既存保存データのsource-context割当は、表示時に「主体は推定」と扱い、保存済みデータを一括変換しない。
6. 組込・public・実行時のカスタムプロンプト補足を揃える。旧指示が残る場合でも末尾の新しい主体推定契約を優先することを明記する。通常の役割一覧・ID照合・原文参照検証を維持する。
7. サンプルの一回の正規化応答から推定主体・カード・接続を構築できる回帰試験、保存読込・無効フラグ・部分修復・出力・画面試験を行う。型検査、全テスト、build.batで配布物まで更新する。

## 自己レビューと修正点

- 推定許可の一文を足すだけでは、既存の未割当指示と衝突する。主体ポリシー本体と帰結ポリシーを修正し、カスタム設定には新契約を最後に補足する。
- 見出しや本文へ「推定」を埋め込むと共有イベントの文章が汚れる。割当の任意フラグとして管理し、表示時に付記する。
- 「明示主体との区別不要」は詳細な区分を不要とする指定であり、推定表示そのものは必要。推定フラグだけ保持する。
- イベントの発生は記録され、主体だけが推定の場合、イベント全体をassessmentへ変更しない。
- 複数主体イベントで一主体だけが推定なら、その主体のカードだけへ表示する。主体が同じでも別イベントまで推定扱いにしない。
- 形式が正しいことは推定精度の証明にならない。疑似LLM試験と画面試験は取込・描画の確認であり、実モデルの意味判断評価とは区別する。
- 既存の5.0保存データは引き続き読めるようにする。旧形式の変換機能は作らない。主体がどうしても推定できない場合の未割当は残す。


## 実装・検証状況

正規化の任意inferred修飾子、保存の任意フラグ、簡素な主体推定表示、chain-delta-3、組込・実行時プロンプトを実装した。推定理由・詳細区分を新しい割当に要求しない。疑似LLMで正規化1通信からカードと接続が構築されること、イベント記録区分・割当単位の表示・保存検証・SVG・レポート・限定修復・旧保存読込を確認した。実モデルの推定精度評価は未実施。最終の型検査・全テスト・配布ビルドを実行する。
