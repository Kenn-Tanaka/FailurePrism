# VTAイベント抽出・カード整理・レーン表示 変更計画

作成日: 2026-10-28。状態: 実装・自動検証済み。実装上の構成と確認範囲は第11節を参照。

本書の全文正規化・引用検証部分は2026-10-29に更新された。[現行のテキスト変換・TSV台帳仕様と自己点検](TEXT_LEDGER_SPEC.md)を優先する。カード整理・レーン表示の計画は継続する。

## 1. 目的と範囲

入力全文をLLMで正規化し、イベントと主体への割当を整理した後、冗長な表示カードと空レーンを除いてから接続線を生成する。前段の正規化方針と後段の図の簡素化方針を一つの処理系列として扱う。

原文、イベント、主体、関与、根拠を保持し、図の簡素化による情報の消失を防ぐ。「不要カードの削除」は表示対象からの除外とし、イベントや主体への関与の削除とは区別する。旧形式データの変換機能は実装しない。

## 2. 処理順序

1. 入力原文を保持し、参照用の位置IDを付与する。
2. 入力全文を原則1回のLLM呼出しで正規化する。
3. 正規化結果の形式・参照・引用・網羅状況を検証する。
4. イベントと主体・役割・関係を確定し、主体別のカードを構成する。
5. 表示上必要なカードを保護し、条件を満たす冗長カードを表示対象から除外する。
6. カードのないレーンを自動非表示にし、手動の表示指定を適用する。
7. 残ったカードの順序・配置を確定し、同一レーンの時系列線とレーン間の関係線を生成する。
8. 整理結果を確認・修正できる状態で提示し、既存の確認操作で図へ反映する。

意味上の関係の抽出は手順2で行ってよいが、描画用エッジの生成は手順7で行う。変動判定は抽出・割当の後に行い、通常事象であることをカード除外の理由にしない。

## 3. 全文正規化と抽出

### 3.1 LLMの責務

- 書式に依存せず、独立した出来事、主体の同一性、役割、時刻・前後関係、明示された伝達・影響関係を整理する。
- 出来事ごとに原文位置と引用を付ける。事実の記録、当事者の主張、評価・推定を区別し、矛盾する記述を無断で統合しない。
- 同じ出来事の重複記述を統合するが、異なる出来事を要約して一つのイベントにしない。時刻不明だけを理由にイベントIDを統合しない。
- VTAに不要な重複説明、文献情報だけの記述、事例の経過に関与しない一般論等を図作成用データから除く。イベントの理解や変動判定に必要な背景は根拠・補足として残す。判断が曖昧なものは要確認とする。
- 採用しない記述にも原文参照と除外理由を付ける。原文自体は変更しない。

正規化応答は、根拠、イベント、主体、関与、意味上の関係、背景情報、除外情報を含む構造化データとする。後続段で同じ意味解釈をLLMに繰り返し依頼しない。

### 3.2 決定論的処理の責務

- ID発行・参照整合性・引用一致・参加主体の存在・役割値・重複・前後関係の循環を検証する。
- 原文の各参照区間について、イベント根拠、背景、除外、要確認のいずれかへの対応を検証する。区間が対応済みであることだけでは、その区間内の全出来事が抽出できた保証にはならない。
- 正規化結果から主体別カードを作成する。同一イベントの主体別カードには同じイベントIDを持たせる。
- 順序不明の複数イベントを同一カードにまとめる既存方針は、イベントIDを個別に保持した表示上のグループとして扱う。異なる時刻・明示的な前後関係があるイベントを同一カードにまとめない。
- 全文一括処理に置き換える経路では、「時系列」という見出しや行頭の日付を抽出対象選定の必須条件にしない。原文位置の付与は参照のために行う。

通常処理は正規化1パスとする。不正な応答には対象を絞った修復を上限付きで行い、通信失敗・キャンセル・出力途中切れを成功として扱わない。コンテキスト／出力上限を超える場合は明示して停止し、黙って全文の一部だけを採用しない。除外情報の再採用では必要な部分だけ再解析する。

## 4. カード整理規則

### 4.1 候補

主体への割当後の全カードを基準に、そのレーンにカードが1枚だけ存在し、そのカードの各イベントIDが他レーンにも存在する場合を候補とする。タイトルや本文の類似性では判定しない。

接続点として表示するノードも1枚と数える。複数イベントを含むカードは、そのすべてのイベントについて他の表示カードが残る場合だけ除外できる。

### 4.2 保護と決定手順

1. ユーザーが明示表示・手動追加したカード／レーン、手動の接続点指定、補足や対策・BREAK等の編集を持つ対象を保護する。
2. 根拠のあるレーン間の伝達・影響関係について、必要な主体の端点カードを保護する。端点主体が曖昧なら候補を勝手に一つへ絞らず、該当カードの除外を保留して要確認とする。
3. イベントごとの表示カード数を数える。候補を原文由来の安定した主体順とIDで処理し、除外後も各イベントが1枚以上残ることを確認して除外する。
4. 除外理由、対応するイベントID、残存カードを記録する。

同じイベントのカードが単独レーンに複数ある場合、すべてを一括で削除しない。保護対象がなければ安定した主体順の先頭を優先して残すよう、後方の候補から判定する。画面のレーン並べ替えで代表カードが変わらないよう、表示順とは別の安定順を使う。

この規則では単独カードを除くとそのレーンが空になるだけで、他レーンのカード数は変わらない。候補を一度列挙して残存数を更新すれば、反復による新たな候補探索は不要である。関係端点の保護も先に確定し、除外と復元の反復を発生させない。

## 5. レーン管理と手動操作

- レーンごとに「自動」「表示」「非表示」を持たせる。「自動」は整理後にカードがあれば表示、なければ非表示とする。
- 「表示」は、その主体に割り当てられた除外カードも復元し、以後の自動整理から保護する。表示するカードのないレーンも残す。
- 「非表示」は明示的なユーザー指定として優先し、カード・関係を保存したまま図から除く。見えない端点への線は描かず、別の主体に接続し直さない。
- 非表示により図上から消えるイベントや関係の件数を一覧で示す。自動整理の「各イベント最低1枚」は手動非表示に対して強制せず、ユーザーが指定していない別レーンを勝手に開かない。
- レーン管理一覧に全レーン、状態、表示カード数／割当カード数、非表示理由、表示・非表示・自動への切替、追加、順序変更を用意する。
- 追加レーンは明示表示として作成する。空でも自動非表示にしない。名称の重複を防ぎ、内部参照は主体IDで管理する。
- 自動整理は初回の図作成と明示的な再整理操作で行う。再描画・保存・読込のたびには実行しない。イベント／割当変更で保護条件や残存条件が壊れる場合は復元を優先し、新たな除外は再整理で行う。
- 表示切替・整理適用・追加・復元をそれぞれ一つのUndo/Redo操作にする。

既存の「図上では接続点として表示」は、レーン非表示や冗長カード除外と別の属性として維持する。接続点は図に存在し、線も保持する。

## 6. 接続線と配置

- 整理後に確定した各レーン内の隣接カードだけを、過去から後のイベントへ接続する。中間カードを飛び越えない。
- レーン間の線は、根拠のある関係と、その関係が指定するイベント・主体から生成する。同じイベントIDを共有することだけでは線を追加しない。
- 主体不明の端点を、整理後にカードが1枚になったことだけを理由に確定しない。曖昧さは整理前の関与情報に基づいて判定する。
- 再表示時は保存したカード属性・座標・補足・接続点指定を復元する。列内の相対位置を保ち、レーン順や衝突のため調整が必要な場合だけ配置を補正する。
- 手動エッジとBREAK・ラベル・方向等を保存し、有効な端点間の属性を維持する。接続の再構成で削除・変更が必要な手動線は、既存の自動修正と同様に差分を示して適用する。
- 図とSVGは同じ表示対象を使用する。説明欄は表示カードに追従し、除外カードは管理一覧から確認・復元できるようにする。

## 7. データ構造と保存

正規データと表示データを分離する。

- 正規データ: 原文、根拠、個別イベント、主体、関与、意味上の関係、全カード参照、背景／除外記録。
- 表示設定: 主体IDによる全レーン順、表示モード、除外カードIDと理由、カードごとの位置・補足・接続点指定、手動エッジと編集属性。
- 描画データ: 上記から作る表示レーン・ノード・エッジ。非表示対象を正規データの欠落と解釈しない。

保存・下書き・Undo/Redoは正規データと表示設定の両方を対象とする。主体名変更や並べ替えで参照が切れないよう、名前ではなくIDで保持する。

正規化情報と表示設定を保存契約へ追加するため、Project形式とanalysis形式を次版へ更新する方針とする。旧版は明確なメッセージで拒否し、変換は実装しない。新形式のサンプル、テスト用データ、インポート／エクスポート、下書き復元を同時に整合させる。

レポート生成・変動判定には正規データを使い、表示の簡素化だけで関与や対策を失わないようにする。図の可視性と分析対象からの除外は別の意味であることをUI・要件に明記する。変更検知は生成に実際に使用したデータを基準とし、表示だけの変更を分析内容の変更と混同しない。

## 9. 実装順序と受入確認

1. 新データ契約と表示／実削除の区別を実装し、保存復元・履歴の土台を確認する。
2. 全文正規化、検証、カード構成を実装し、原文から個別イベントへの追跡を確認する。
3. 決定論的な整理計画と保護条件を実装し、純粋関数として検証する。
4. 整理後の描画投影・接続生成、レーン管理、復元を統合する。
5. 説明欄・SVG・分析機能・保存・文書・サンプルを整合させる。

必須の検証例:

- 同じイベントが2本／3本の単独レーンにある場合、すべては消えない。
- 複数イベントを含むカードでは、一部だけ重複しても除外しない。
- 保護された関係端点、手動カード、接続点、補足、排除対策、BREAKを失わない。
- 主体不明の関係が整理によって誤って別主体に確定されない。
- 自動非表示、手動表示、手動非表示、空レーン追加、再表示、並べ替えの組合せが決定規則どおりになる。
- 同じ入力への再整理は同じ結果になり、適用済み状態への再適用は変化を生まない。
- ドラッグや本文編集を行っても、非表示カードの関与・位置・補足が消えない。
- 隣接線の不足・飛び越しがなく、手動線の属性とユーザーの編集意図が保存される。
- 保存再読込、下書き復元、Undo/Redoで全情報が戻り、SVGと画面の表示対象が一致する。
- 原文形式を変えた同等内容（見出しなし、通常文章、箇条書き、表等）を正規化できる。別時刻の出来事を統合せず、重複だけを統合する。
- 提供された羽田事故の実例で、滑走路停止位置通過、注意喚起開始、滑走路上停止、衝突等が個別イベントとして保持される。明示された通信の送受信主体が保持される。
- 途中切れ、引用不一致、参照欠落、キャンセル時に不完全な図で既存図を置換しない。

実装完了前に `npm run typecheck` と `npm test` を実行する。配布成果物を更新する段階で `build.bat` を実行し、`start-all.bat` で起動した画面にも変更が反映されることを確認する。実LLMによる抽出品質はモックテストと区別して検証・報告する。

## 10. 自己レビューと計画への反映

| 検討点 | 問題 | 計画に反映した対応 |
| --- | --- | --- |
| 全カード消失 | 単独レーンを一括判定すると同じイベントの全カードが消える | 安定順・残存数更新・イベントごと最低1枚 |
| 図の意味の変化 | 同じイベントの別主体カードに線を移すと送受信主体が変わる | 意味上の端点を整理前に保護し、付替え禁止 |
| 見かけ上の曖昧さ解消 | 整理で候補が減った結果を主体確定の根拠にしてしまう | 整理前の関与情報で曖昧さを判定 |
| 復元不能 | 現行reconcileは図上にないカードと関与を消す | 正規データと表示状態を分け、実削除を明示化 |
| 復元直後の再除外 | 再描画で整理すると手動表示が維持できない | 明示表示の保護と整理の実行契機を限定 |
| 多イベントカード | 一つのイベントの重複だけで除外すると他のイベントを失う | 全イベントの残存を確認 |
| 不要な反復 | 除外・復元を反復すると不安定になりうる | 保護を先に確定し、単独候補を一巡 |
| 接続点との混同 | 既存の非表示属性を流用すると点や線の扱いが変わる | 接続点、カード整理、レーン非表示を別属性にする |
| 手動指定との衝突 | 最低1枚を強制するとユーザーの非表示指定を覆す | 最低1枚保証は自動整理に適用。手動非表示は優先し件数を示す |
| 分析内容の欠落 | 表示ノードだけを分析すると非表示の主体・対策が消える | 分析は正規データ、描画は表示投影を利用 |
| 正規化の過剰除外 | 「不要」の判定で必要な経過や背景まで失う | 原文保持、除外理由、要確認、再採用経路、実例で品質確認 |
| 全文1パスの限界 | 長い入力を受けても出力上限・抽出漏れは残る | 途中切れ検知、参照対応の検証、限定修復、実LLM評価 |

結論: 実装可能。ただし表示ノードの配列をフィルタするだけの変更では不十分であり、保存・編集反映・分析入力まで一貫して正規データと表示を分離する必要がある。構造的な整合性は決定論的に保証するが、LLMの意味理解や不要記述判定の正しさは原文との実例比較で確認する。カード数だけで主体の分析上の重要性は判断できないため、除外理由の可視化と手動復元を必須とする。


## 11. 実装結果と確認範囲

- 全文正規化、構造・引用・参照検証、最大2回の修復、選択引用の再抽出を実装した。正常時の意味解析はLLM呼出し1回である。
- 正規カードと保存用nodesをすべて保持し、presentationからvisibleSchemaで可視データを導出する構成にした。表示フィルタの結果を編集用データに書き戻さず、reconcileAnalysisによる関与の誤削除を防ぐ。座標は全レーン基準で保持し、描画・ドラッグ時に可視列との間で変換する。
- レーン管理、整理候補の確認、手動表示・非表示・追加、表示復元、Undo/Redo、保存・下書き、説明欄・SVGを実装した。SVGでは可視範囲に加え、既存の空レーン除外等の出力設定を適用する。
- Project形式3.0／analysis形式3とし、旧形式は拒否する。変換機能は追加していない。新しいVTAサンプルをsamples/sample-project.vta.jsonに追加した。
- 全334テスト、型チェック、build.bat（テスト省略なし）、配布ZIP作成が成功した。全文正規化・部分修復、複数時刻のカード分離、整理・保護条件、座標変換、復元、履歴、SVGを検証した。
