# VTA-Editor ノード位置編集拡張 実装仕様書

文書版: 1.0  
状態: **実装済み。自動テストで検証済み。画面上の手動受入確認は未実施。**  
対象: 見出しのみ表示でのカード移動、および両表示モードでの接続点移動。

本書は修正計画とその自己レビューを実装可能な仕様にまとめ、実装結果を記録する。現行の[技術リファレンス](REFERENCE.md)と[要件定義書](REQUIREMENTS.md)のうち、移動・配置保存・接続修正・SVG出力に関する変更を定義する。

## 1. 目的と適用範囲

次の4通りで、ノードをドラッグして位置を変更できるようにする。

| 表示モード | カード | 接続点（`is_hidden=true`） | 保存先 |
| --- | --- | --- | --- |
| 詳細表示 | 移動可能 | 移動可能 | `position` |
| 見出しのみ表示 | 移動可能 | 移動可能 | `compact_position` |

単体移動と複数選択移動を対象とする。接続点の移動によって、カード再表示、ノードの削除・排除、所属レーン変更、接続関係変更を行わない。接続点からの端子操作による新規接続は従来どおり無効とする。

ドラッグに伴う表示位置はモード別に保持する。ノードID、所属レーン、内容、対策、接続線は共通データとする。表示モードを切り替えるだけでは、座標の確定、Undo履歴の追加、未保存状態への変更を行わない。

## 2. 実装前の動作と実装後の変更

| 箇所 | 現行動作 | 変更後 |
| --- | --- | --- |
| `VTACanvas.tsx` | コンパクト表示は毎回自動配置し、ドラッグと位置通知を無効化 | モード別の保存配置・移動中配置を描画し、両モードで移動を受け付ける |
| `nodeGeometry.ts` | 接続点を `draggable: false` として投影 | 移動可能な接続点へ投影し、保存座標への逆変換を共通化 |
| `vtaStore.ts` | 接続点の位置・寸法通知をともに除外 | 位置通知は変換して処理し、点の寸法で元カード寸法を上書きしない |
| `layout.ts` | 通常の計算でも保存座標へ重なり調整を適用 | 保存配置の解決と、明示操作に伴う自動整列・重なり調整を分離 |
| 接続自動修正 | 詳細表示へ戻して、その上下順から候補を作る | 表示中の上下順から候補を作り、他方の表示に必要な再配置も確認対象にする |
| `svgExport.ts` | 保存座標を無視して常に再配置 | 選択した表示モードの保存配置を使用する |

## 3. 保存データと座標の定義

### 3.1 ノード属性

`VTANodeData` に任意の `compact_position` を追加する。

```typescript
type VTAViewMode = 'detail' | 'compact';
type NodePosition = { x: number; y: number };

interface VTANodeData {
  // その他の既存属性は省略
  position?: NodePosition;
  compact_position?: NodePosition;
  is_hidden?: boolean;
  hidden_card_height?: number;
}
```

- `position`: 詳細カードの左上を基準とした図座標。
- `compact_position`: 見出しのみカードの左上を基準とした図座標。
- 非表示ノードについても、この2属性は元カードの左上座標を保持する。接続点の左上座標や中心座標を直接代入しない。
- 座標はReact Flowの図座標とする。画面ピクセルやズーム・パンの値を保存しない。
- `hidden_card_height` は詳細カードの非表示化時の高さとして維持する。見出しのみ表示のカード高さは `compactNodeHeight(title)` で求め、詳細表示用の実測値を流用しない。
- `is_hidden` は両表示に共通する。非表示指定そのものをモード別にはしない。

### 3.2 保存配置の解決

`resolveViewLayout(schema, mode)` 相当の共通処理を設け、保存データからそのモードの未投影ノード、エッジ、レーン範囲を返す。

1. 選択したモードの有効な保存座標があれば、その座標を採用する。
2. 未設定ノードには、そのモードの高さを使った既存BT自動配置を初期値として使う。
3. 保存済みノードを描画のたびに自動整列し直さない。追加ノードの初期配置や内容変更による重なり調整は、対応する編集操作で処理する。
4. 単なる表示切替では結果を保存しない。初回の手動移動が確定した時点で、表示中モードの全ノードの解決済み座標を保存する。これにより、移動していないノードだけが次回描画で別の自動座標へ戻ることを防ぐ。
5. ファイル内の有効な座標は、読込だけを理由に別の順序へ並べ替えない。重なりが残っている場合は、接続自動修正の確認で対象を通知できること。

自動整列は `placement: 'auto'` 相当の明示指定に分離し、そのモードの保存座標を参照せずに計算する。保存配置の解決は `placement: 'saved'` 相当とする。既存の `forceRecompute` と新しい保存位置の優先順位が競合しないよう、呼び出し側を統一する。

### 3.3 取込と互換性

- `compact_position.x/y` は有限の数値だけを受理する。負の座標を許可する。空文字・数値文字列・NaN・Infinity・不完全なオブジェクトは採用しない。
- 不正な新属性はその属性を除外して警告を返し、その他が有効なプロジェクト全体を不必要に拒否しない。
- ファイル・下書き復元の `restorePresentation=true` の経路で採用する。AI抽出では `compact_position` を破棄する。
- 新属性がない旧ファイルは従来どおり読み込み、見出しのみ表示の初期配置を計算する。既存の `position` の意味は変更しない。
- 任意属性の追加として、既存のプロジェクト形式バージョン `1.0` を維持する。旧アプリで新ファイルを読み書きした場合、新属性の保持は保証しない。
- LLM向けJSONでは新属性を除外する。座標と表示属性は分析内容ハッシュに含めず、位置移動だけでレポートを「古い」と判定しない。

## 4. 接続点の座標変換

### 4.1 投影と逆変換

カード左上座標を `P`、当該モードのカード幅・高さを `W/H`、接続点の操作領域幅・高さを `S` とする。現行値は `W=260`、`S=20`。点の描画半径は従来の4pxを使う。

```text
カード中心 C = P + (W / 2, H / 2)
接続点の操作領域左上 J = C - (S / 2, S / 2)
元カード左上 P = J + (S / 2, S / 2) - (W / 2, H / 2)
```

`nodeGeometry.ts` に投影・逆変換を集約する。接続点へ投影済みのノードを、未投影ノード用の `getDisplayRect` へ再度渡さない。寸法・座標の基準を型またはAPI境界で区別する。

### 4.2 ドラッグ中の変換

ドラッグ開始時の元カード座標 `P0` と表示座標 `D0` を記録し、React Flowから受け取る現在表示座標 `D` を次のように変換する。

```text
Δ = D - D0
P = P0 + Δ
```

通常カードでは `D0=P0`。接続点では `D0=J0`。複数選択では各ノードについて独立に変換する。ドラッグ開始時からの差分を用い、イベントごとに総移動量を加算しない。

点の20pxという寸法通知は元カードの幅・高さや `hidden_card_height` に反映しない。接続点の移動通知と寸法通知を別に扱う。

## 5. ドラッグ処理と履歴

### 5.1 状態管理

Storeに一時的なドラッグ状態を持たせる。最低限、プロジェクトID、表示モード、変更前スキーマ、ノード別の開始表示座標・開始保存座標・寸法、移動中の未投影ノードを保持する。この状態はプロジェクトや下書きへ保存しない。

既存の詳細表示用 `nodes` へコンパクト座標や投影済みの点座標を直接書き込まない。キャンバスは表示モードを指定してレイアウトを取得し、ドラッグ中は当該セッションの配置を描画する。寸法キャッシュも表示モード別に管理する。

### 5.2 開始・移動・完了

1. **開始**: 表示中の配置を固定し、変更前スナップショットを取得する。未保存の自動座標もUndoで同じ図へ戻せるよう、履歴用スナップショットには有効座標を含める。
2. **移動中**: 第4章の変換で未投影座標を更新し、描画用に一度だけ投影する。線の端点・経路・ラベル位置を追従させる。履歴追加・下書き保存は完了時まで行わない。
3. **完了**: 列中央スナップ設定が有効なら、ドラッグ開始時との座標差がある移動対象だけを所属レーン中央へ横方向に合わせる。接続点は可視中心を基準に元カード座標へ換算する。その後、そのモードの可視矩形に基づき、レーン内の重なりを解消する。接続点の占有高さには20pxを使い、隠した詳細カードの高さを使わない。
4. 位置差が0.001図座標単位を超えるノードがある場合だけ、全ノードの当該モード座標を確定する。移動対象と重なり調整で動いたノードをまとめて1件のUndo履歴にする。
5. 未保存状態、レーン背景範囲、自動保存、ビューのキャッシュを更新する。移動がなければ履歴と保存データを変更しない。

重なり調整は既存の `enforceLaneVerticalSpacing` の基準を使い、表示上の上から下の順序で後続ノードを押し下げる。相対順序の判定には当該モードの可視矩形を使う。調整前後の双方で点の投影を重ねて適用しない。

ドラッグでは `lane`、`time`、`sequence_order`、エッジを変更しない。横方向へ移動して隣の列に重なっても、所属変更はノード編集画面で行う。上下の並びを変更した結果、飛び越し線等が生じた場合は第8章の明示的な接続修正で処理する。

列中央スナップはキャンバスのチェックボックスで切り替え、初期状態は無効とする。設定はブラウザーの `vta_snap_to_lane_center` に保存し、プロジェクトデータ・Undo履歴・未保存状態には含めない。重なり調整だけで動いたノードとドラッグ開始位置に戻したノードはスナップ対象にしない。複数選択で別レーンのノードも直接移動した場合は、それぞれの所属レーン中央に合わせる。

### 5.3 中断と複数イベント

- Escapeはドラッグを取り消し、開始時の表示へ戻す。履歴を追加しない。
- ドラッグ中の表示切替・自動整列・接続修正・Undo/Redoは、先にドラッグを取り消してから処理する。
- プロジェクト読込・サンプル切替・AI生成による図の置換・ツールの非アクティブ化はドラッグ状態を破棄する。旧プロジェクトの終了イベントを新しい図へ適用しない。
- 複数選択移動は1セッションとして確定する。個別ノードの終了通知ごとに履歴を積まない。
- ドラッグ中に来た寸法通知で開始時の座標変換基準を変えない。必要な最終寸法補正は完了処理と同じ履歴へ含める。

## 6. カードと接続点の切替

非表示指定は引き続きユーザーの明示操作でのみ行う。

### 6.1 カードから接続点へ

- 両モードの現在有効な配置を取得し、対象ノードのカード中心を求める。未設定の配置は当該操作の中で確定する。
- 詳細カードの高さを `hidden_card_height` に保持する。コンパクト側にはそのモードの高さを使う。
- 点の中心が、各モードで直前に表示していたカードの中心に一致するよう投影する。非表示切替によって他のカードを自動で詰めない。
- 位置の確定と非表示属性の変更を1件の履歴へ含める。

### 6.2 接続点からカードへ

- 各モードの点の中心 `C` を取得し、復元するカードの新しい幅・高さから `Pnew = C - (Wnew/2, Hnew/2)` を求める。
- 本文・見出しが非表示中に編集されていても、点の中心を基準に復元する。その後、必要なレーン内の重なり調整を行う。重なり調整による位置の移動は許容する。
- 実測高さが描画後に確定する詳細カードには、一時的な中心基準を保持する。初回の寸法補正を再表示操作へ統合し、別のUndo履歴を追加しない。Undo・図の置換・別の編集開始時には古い補正を適用しない。
- 非表示中の見出し変更でコンパクトカードの計算高さが変わる場合、`compact_position` を逆変換し直し、点の中心を保つ。詳細側は保存済み `hidden_card_height` を基準にする。

## 7. 他の操作との整合

| 操作 | 座標と履歴の規則 |
| --- | --- |
| 表示切替 | 保存済みの各モード配置を表示。単なる切替では履歴・未保存状態を変更しない |
| BT自動整列 | 両モードで使用可能にする。表示中モードだけを再計算・保存し、1件のUndoへ記録 |
| 列順序変更 | 両モードの有効配置を基準に、所属列の移動数 × `LANE_WIDTH` をX座標へ加算。Yと列内Xオフセットを保持。1件のUndoへ記録 |
| ノード追加 | 新規ノードの両モード初期位置を計算。既存保存位置を基準に、必要なレーン内重なり調整のみ行う。追加操作へまとめる |
| ノード削除 | 当該ノードの両モード位置と一時キャッシュを除去。残りの保存配置を維持 |
| 所属レーン変更 | 両モードのX座標を新旧列番号差だけ移動。Yを基準に移動先レーンの重なりを調整。内容変更と同じ履歴へまとめる |
| 時刻・本文・見出し編集 | 時刻や本文変更だけで保存位置を全消去しない。表示サイズ変更に必要な調整のみ当該編集へまとめる。時系列の全再配置はBT自動整列で行う |
| 接続線の編集 | 保存配置を維持し、経路を再描画。配置と接続の矛盾の解消は接続自動修正で行う |
| Undo/Redo | 両座標属性、非表示属性、接続を一緒に復元し、両ビューのキャッシュを再構築。操作中の表示モードは維持 |
| 図全体の置換 | 旧図の配置・寸法キャッシュ・ドラッグを破棄。新図から初期配置を構築 |

「図上表示」は現在表示しているモードのノード中心へフォーカスする。点のクリックは説明欄への移動として維持し、ドラッグ終了をクリックとして誤処理しない。

## 8. 接続自動修正の拡張

### 8.1 両モードの順序が異なる場合の規則

2系統の座標を独立に編集できるため、同一レーンの上下順が表示モード間で異なる場合がある。一方、エッジは共通であり、異なる2つの順序を同時に同じ隣接線で表すことはできない。

そのため、通常ドラッグは選択したモードの配置だけを編集し、**接続自動修正を適用する時点で、表示中の順序を両モードの基準にする**。他方の手動配置を変更する場合は、必ず修正プレビューへ含める。

### 8.2 候補の作成

1. 現在の表示モードを維持したまま、そのモードの未投影レイアウトを取得する。詳細表示へ強制的に戻さない。
2. 可視矩形から同一レーンの下→上の順序を取得する。接続点も1ノードとして数える。重なり・位置欠落・不正な接続先がある場合は、対象を示して適用を止める。
3. `repairLaneConnections` を使い、不足線の追加、飛び越し・重複線の削除、逆向き線の補正を計画する。既存のメタデータ保存規則を維持する。
4. 候補エッジを使って、他方の表示の有効配置と順序を調べる。未設定座標は候補スキーマから自動配置する。
5. 順序が異なる、または重なりにより確定できないレーンを、他方の表示の再配置対象とする。同じ順序で重なりがないレーンは位置を保持する。

### 8.3 他方の表示の再配置

対象レーンについて、表示中モードの順序を上→下に並べ直し、次の手順でY座標を計算する。

- 再配置前の、そのレーンの最も上の可視矩形のY座標を起点にする。
- 上から順に可視高さと `VERTICAL_GAP` を加えて配置する。点の可視高さは20px。
- 各ノードのX座標を保持する。点は配置後の可視矩形から第4章の逆変換を行い、元カード基準のY座標を保存する。
- 対象外レーンと、操作中モードのノード位置を保持する。未設定位置も含めて必要な配置を確定し、後続の描画で再配置が失われないようにする。

この処理は他レーンとの時刻の水平揃えより、レーン内の順序と非重複を優先する。全体を整列し直したい場合はBT自動整列を使用する。

### 8.4 確認・適用・取り消し

- プレビューに基準の表示モード、線の変更一覧・件数、削除されるラベル・分類・BREAKを示す。
- 他方の表示の再配置がある場合、表示モード名、対象レーン、対象ノード数、変更前後の上下順を示す。
- 線の変更が0本でも、他方の順序をそろえる必要があれば適用可能とする。両方とも変更がない場合にのみ「修正は不要」とする。
- 確認中の変更検出には、プロジェクトID、表示モード、スキーマ、両モードの有効配置を含める。変化があれば候補を更新し、古い候補を適用しない。
- 接続変更と必要な他方の再配置を、1回の `commitVTAChange` と1件のUndoで確定する。
- 適用前に、保存復元した両モードで隣接線の不足・飛び越しがないことを検証する。自動整列後も修正した時系列線の順を維持する。レーン間に循環がある場合の、同一レーン時系列線を優先する既存方針を利用する。
- 接続変更を伴う場合は既存のハッシュ比較でレポート最新性を判定する。配置変更だけの場合はレポートを古い扱いにしない。

## 9. SVG出力

- 出力画面の見出しのみ表示の選択は、画面で操作中のモードを初期値とする。ユーザーは出力モードを切り替えられる。
- 指定モードの保存配置を優先する。未設定位置だけを同じ配置解決処理で補完し、全ノードを `forceRecompute: true` で並べ直さない。
- 現在の有効配置・寸法が利用可能なら利用し、点の中心と接続端点の計算には画面と同じ幾何処理を使う。SVG出力は保存データ・履歴を変更しない。
- 空レーンを除外するときは、各ノードのX座標へ `(出力時列番号 - 元の列番号) × LANE_WIDTH` を加算する。列内の手動オフセットとY座標を維持する。
- 出力全体の原点移動・余白付与は従来どおり許可する。比較対象はノード同士の相対配置と接続点の中心位置とする。
- SVG用フォントによる文字幅差は許容する。文章の折り返しを理由に保存された上下順を自動変更しない。

## 10. UI仕様

- ツールがアクティブな場合、両モードのカード・接続点をドラッグ可能とする。
- 接続点は通常時 `grab`、ドラッグ中 `grabbing` 相当のカーソルにする。操作領域は現行20pxを維持し、点の可視半径は変えない。
- 接続点の補足表示に「ドラッグで移動、クリックで説明欄を表示」を示す。
- 見出しのみ表示の説明から「移動できない」という説明を除き、両モードの配置を個別に保持することを示す。
- 「BT自動整列」はコンパクト表示でも有効にし、表示中の配置が対象であることを説明する。
- 未保存表示・自動保存・Undo/Redoの操作は通常カードと統一する。

## 12. 受入条件と検証

| ID | 条件・操作 | 合格条件 |
| --- | --- | --- |
| MV-01 | カード／接続点 × 詳細／見出しのみの4通りで単体ドラッグ | 点やカードがポインターに追従し、終了時に表示中モードの位置が保存される |
| MV-02 | カードと接続点を同時選択して移動 | 同じ移動量が適用され、重なり調整を含む全変更が1回のUndo/Redoで復元される |
| MV-03 | 非表示ノードへ多数回の位置通知・20px寸法通知 | 座標変換による累積ずれがなく、元カードの寸法が20pxへ変わらない |
| MV-04 | 初回コンパクト移動後に表示切替を繰り返す | 両モードがそれぞれの配置へ戻り、移動していないノードも勝手に再整列されない |
| MV-05 | 非表示中に本文・見出しを変更し、点を移動してからカード再表示 | 点の中心を基準にカードを復元し、必要な重なり調整後も同一レーン内の上下順を保持 |
| MV-06 | ドラッグをEscape、ツール切替、図の置換で中断 | 中途半端な位置や履歴が残らず、旧図の終了通知が新図へ反映されない |
| MV-07 | 各モードでドラッグ→Undo→Redo→下書き復元・JSON再読込 | 両座標、非表示状態、接続が確定時の状態へ戻る |
| MV-08 | 旧ファイル、新属性なし、不正な新座標を含むファイル | 旧データを利用でき、不正座標は除外・警告され、描画を壊さない |
| MV-09 | 列順序変更、所属変更、ノード追加・削除 | 両モードの列位置が整合し、対象外の保存配置が意図せず失われない |
| MV-10 | 両モードでBT自動整列 | 表示中モードだけが再整列され、Undoで直前の手動配置へ戻る |
| MV-11 | 詳細とコンパクトで同一レーンの上下順を変え、接続自動修正 | 操作中モードを維持し、線変更と他方の再配置を事前確認でき、適用後は両方の隣接規則を満たす |
| MV-12 | 線変更なし・他方の順序不一致だけがある図を修正 | 再配置候補を提示して適用でき、正常な図への再実行では履歴を増やさない |
| MV-13 | 修正プレビュー中に配置・モード・プロジェクトが変化 | 古い候補を適用しない |
| MV-14 | 手動移動したカード・点を両モードでSVG出力 | 相対配置と点への接続が画面と整合し、空レーン除外では列幅分だけX座標を補正 |
| MV-15 | 移動後にレポート最新性・LLM用JSONを確認 | 位置移動だけでレポートが古い扱いにならず、新しい表示座標がLLMへ送られない |
| MV-16 | 接続点をクリック／ドラッグ | クリックは説明欄を表示し、ドラッグ操作では終了時にクリック動作が発火しない |
| MV-17 | 列中央スナップを切り替え、両モードでカード・接続点を移動 | 有効時だけ実際に移動した対象の可視中心が所属レーン中央になり、周囲のノードの横位置を変えない。スナップ結果を1回のUndo/Redoで復元し、設定の切替だけでは図を変更しない |

幾何変換、保存復元、履歴、接続修正、SVGを対象とする回帰テストを実装時に整備する。画面では4通りのドラッグと混在選択を確認する。

検証結果: `npm run typecheck` は成功。VTA関連の `npx vitest run src/tools/vta/features/vta` は19ファイル・127テストすべて成功。全体の `npm test` は279件中277件成功し、ローカルHTTP接続を使う `tests/shell/server.test.ts` の2件が実行環境の `EACCES` で失敗した。画面上での4通りのドラッグ、複数選択、Escape中断は未確認。配布物を更新する際は `build.bat` を通常実行する。
