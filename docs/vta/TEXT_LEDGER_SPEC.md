# VTA テキスト変換・TSV台帳 実装仕様と自己点検

2026-11-11 更新。イベント抽出・正規化台帳・変動要因判定の現行仕様（`event-ledger-15` / `relation-attributes-2` / `chain-delta-3` / `connection-proposal-2` 準拠）。

---

## 1. 処理と責務

1. アプリが入力原文を保持し、段落を `[p1] 原文` の形式でLLMへ渡す。日付や見出しの書式を前提にしない。長い行の分割は参照位置を付けるためであり、LLMには全文を一回で送る。
2. LLMが正規化、独立イベントの分離、主体同定・所属階層・役割、時刻と順序、伝達・影響・依存、背景・除外・要確認を決め、TSV台帳へ変換する。
3. アプリが列数、列挙値、IDの一意性・参照先、描画不能な前後関係の循環や矛盾を確認する。引用文の完全一致、日付の解釈、段落先頭からの時刻補完、段落ごとの強制的なイベント生成は行わない。
4. 確認可能な形式の不正行は最大2回、指定IDの行だけをLLMに修復させる。正常な行は保持し、修復応答による指定外の追加・削除・ID変更を拒否する。
5. 主体別カードを構成し、既存のカード整理・レーン表示ルールを適用した後に接続線を描く。

時刻不明の複数イベントも個別IDを持つ。同一カードにする場合は、LLMが別の共有カード表で明示する。イベント時刻の欠落だけを理由にアプリがまとめることはない。

## 2. 台帳形式

セクションは、必須6セクション（`[主体]`、`[イベント]`、`[関係]`、`[共有カード]`、`[整理]`、`[帰結]`）および任意3セクション（`[表記]`、`[表現]`、`[仮判定]`）から構成される。空でもセクションを出力する。各表の見出しは `eventLedger.ts` の `LEDGER_HEADERS` に定義する。末尾は必ず `[完了]`。

| 表 | 列 | 説明 |
| --- | --- | --- |
| **主体** | ID、名称、種類、報告焦点、所属・上位主体、焦点根拠 (6列) | 種類は `person`/`organization`/`machine`/`other`。焦点は `reporter`/`high`/`mid`/`low`。所属は上位組織ID（ADR-0010, ADR-0013, ADR-0023, ADR-0033） |
| **イベント** | ID、時刻、見出し、内容、主体と役割、原文参照、区分 (7列) | 区分は `recorded`/`claim`/`assessment`。末尾区分省略時は `recorded` を安全自動補完（ADR-0032） |
| **関係** | ID、種類、元イベント、元主体、先イベント、先主体、原文参照、リソース、実施状態、受領確認 (10列) | 種類は `before`/`transfer`/`impact`/`mutual`/`common`/`dependency`。片側未指定関係の安全格下げ対応（ADR-0030） |
| **共有カード** | ID、主体、イベントID一覧 (3列) | 同一主体で時間差・因果関係のない複数イベントを1枚のカードへ集約 |
| **整理** | ID、区分、原文参照、要旨、理由 (5列) | 区分は `background`/`excluded`/`review` |
| **帰結** | ID、判定、イベントID、原文参照、理由 (5列) | 判定は `identified`/`not_found`/`uncertain`。損失発生だけでなく機能縮退・緊急停止によるレジリエンス帰結もアンカー（ADR-0002, ADR-0017, ADR-0033） |
| **表記（任意）** | ID、種別、原文表記、統一後、原文参照、理由 (6列) | 種別は `alias`/`typo`。記号正規化一致・段落間補正・非停止安全除外（ADR-0004, ADR-0032） |
| **表現（任意）** | ID、原文参照、検知語句、処理、イベントID、理由 (6列) | 処理は `removed`/`quoted`/`action_only`。主観・過失表現の点検記録（ADR-0004, ADR-0032） |
| **仮判定（任意）** | イベントID、判定、理由、原文参照 (4列) | 判定は `normal`/`variation`/`undetermined`。Stage 1b専用パス（ADR-0001, ADR-0016） |

列間は実タブ、セル内のタブ・改行は禁止し、セル内改行はLLMが空白へ変換する。空値は `-`、ID一覧はカンマ区切り。IDは英字で始まる英数字・ハイフン・下線とし、セクション内で一意とする。役割は `A1:actor,A2:target` の形式。主体名や本文の句読点を区切りとして解釈しない。

種類・役割・記録区分は内部の列挙値を使う。伝達・影響では両端のイベントIDと主体IDが必要。同一イベントの複数主体は本文を繰り返さず、一つの行の役割一覧に記す。

原文参照は `p1,p2` の形式とし、原文引用を台帳に再掲しない。記録・主張・評価を区別する。背景等も原文のコピーではなく短い要旨と理由にする。アプリは参照番号から保持した原文を確認欄に表示する。

## 3. 行単位の修復と中断

修復要求には不正行、見出し、エラー、対応する原文段落、本文を含まないID一覧を渡す。主体・関係・共有カードの修復では関連イベントの参照をたどって原文を絞り、関連イベントの時刻も渡す。原文全文・前回結果全文を再送しない。参照が使えない場合は先頭の少数段落だけを補助文脈として渡し、原文番号や内容をアプリが推測して補正しない。修復で正しく対応できない場合は停止する。

主体行が不正なだけで、主体IDを正しく参照しているイベント行まで一括で修復対象にしない。共有カードの矛盾・前後関係の循環などの複数行にまたがる問題は、関係する表の行を修復対象とする。

正規化で読み取れる台帳は、失敗した修復の前後も最大3件までメモリに保持する。同じプロジェクト・モデル・接続先・入力・プロンプトで再実行すると修復から再開する。更新・アプリ終了を越えて保持する機能ではない。取得成功後はキャッシュを解放する。

ただし同じ不正行が変更なしで返った場合は修復を停止する。修復上限到達時と変更なしの停止時はキャッシュを解放し、次回は全文の正規化から再取得する。通信失敗の場合は修復再開用の台帳を保持する。

transfer/impact/mutual/commonの関係行は、両端のイベントと関与する主体IDを必須とする。LLMが原文から両端を特定できない場合は、修復対象の関係行だけを同じIDの整理review行（原文参照・要旨・理由付き）に置き換えられる。イベントは保持し、アプリ側で主体を補完しない。指定外の行、同じ関係の二重出力、既存整理IDとの衝突は拒否する。

ID重複、未知のセクション、セクション欠落、完了記号欠落など、修復する行IDを一意に特定できない応答は明示的に停止する。途中切れ・通信失敗・キャンセルを成功にせず、既存図を不完全な結果で置換しない。

背景等の再抽出は選択した記録が参照する原文を送り、その範囲の抽出済みイベントを重複防止の文脈としてLLMに渡す。新しいIDはアプリで既存IDと衝突しない名前に付け替える。出来事の同一性はLLMが判断する。

## 4. 変動判定・表示・保存・分析

変動判定もTSVで入出力する。イベント・主体と役割・記録区分・参照原文・背景をテキストで渡し、`[判定]` の4列（ID、判定、理由、原文参照）と `[完了]` を受け取る。判定の原文参照は `source_1/p1` の形式で、当該イベントの参照範囲に限定する。根拠不足は保留。欠落・不正行だけを修復し、正常な判定を保持する。

### 4.1 変動要因の精緻化分類とレジリエンス（Safety-II）極性（ADR-0031, ADR-0033）
`extractVariationFactorFromReason` により、判定理由テキストから以下のメタデータを自動抽出・自己治癒する：
1. **カテゴリ (`category`)**:
   - `departure`: 通常作業からの逸脱（人為的ミス・手順違反）
   - `response`: 先行変動や状態変化への応答（臨機応変な回避・機能縮退）
   - `internal`: 装置・部品故障、ソフト異常、急病等の内部要因
   - `external`: 天候・外乱・外部インフラ途絶
2. **行動レベル (`cognitiveLevel`)**:
   - Rasmussen SRKモデル（`skill` / `rule` / `knowledge`）および失敗学三大要因（過信 / 無視 / 無知）に対応。
3. **極性 (`polarity`)**:
   - `negative`: 負の要因（エラー・事故進展、Amber色）
   - `resilient`: 正の要因（機能縮退・フェイルセーフ・被害抑止・安全停止、Teal色）

保存形式はProject 5.0／analysis 5。イベントの `sourceRefs`、`recordKind`、`classificationSourceRefs`、`variationFactor` と関係・整理記録の原文参照を保存する。新抽出の `facts`／`factIds` は空とする。保存JSONはアプリが生成し、LLMには生成させない。形式3.0以前は拒否し、変換は実装しない。

## 5. 耐障害性と自己治癒契約（ADR-0030, ADR-0032, ADR-0033）

1. **片側主体未指定関係の安全な格下げ・自己治癒（ADR-0030）**:
   複数主体関与事象からの波及線で、片側主体が未特定（`-`）のまま出力された場合、単一主体の自動補完または安全な時系列線（`before`）への自動格下げを行い、関係全体の脱落や巻き添えエラーを防止。
2. **イベント末尾区分（`recorded`）省略の安全自動補完（ADR-0032）**:
   LLMがイベント行末尾の区分列を省略して6列で返した場合、第5列の主体役割が正常であれば自動的に `recorded` を補完してパースを継続。
3. **任意監査セクションの3層防御（ADR-0032）**:
   `[表記]`、`[表現]` において、①記号正規化一致（`cleanPunctuation`）、②段落間自動再探索、③非停止安全除外（本体処理を中断せず警告付きで安全除外）の3段階で保護。
4. **能動的・対話的装置の判定と主要主体昇格（ADR-0033）**:
   `isActiveOrInteractiveMachine` により、モード混乱（Mode Confusion）、自律介入、機能縮退（Graceful degradation）に関与する `machine` 主体を `kindWeight = 2` に昇格し、主要レーンとして死守。受動的な警報表示ツール（ADR-0013）は引き続き抑制。
