# Lightweight LLM Gateway 1.3.2 クイックスタート

## VTA図の配置

VTAキャンバスでは詳細表示・見出しのみ表示のどちらでもカードと接続点をドラッグできます。各表示モードの配置は個別に保存され、Undo/Redoとプロジェクト保存に含まれます。「BT自動整列」は現在表示中のモードを対象にします。接続点はドラッグで移動でき、クリックすると右側の該当説明を表示します。

シナリオ入力後に「イベント・主体を抽出」を押すと、入力全文をLLMで原則1回正規化し、イベント・主体・原文参照のTSV台帳を読み取ってからカード整理と接続を行います。通信が成功した後、左欄に抽出件数と確認画面を表示します。確認欄でイベント本文・時刻・主体の割当と役割を修正し、「確認してVTA図に反映」を押すと図を更新します。複数主体の共通イベントは同じイベントIDを参照し、変動要因はまだ未判定です。「確定したイベントの変動要因を判定」で判定を実行します。後から「イベント・主体の割当を確認・編集」を開けます。プロジェクト読込は形式5.0のJSONのみ対応し、旧形式は変換しません。

ツールバーの「移動後に列中央へスナップ」を有効にすると、ドラッグ終了時に移動したカード・接続点だけが所属列の中央へそろいます。初期状態は無効で、設定はブラウザーに保存されます。

「接続を自動修正」は現在の表示順を使います。もう一方の表示で同一レーンの順序が異なる場合は、修正前に必要なレーン配置の変更を確認できます。SVG出力は選択した表示モードの配置を使います。

「レーン間接続をAIに提案」は、確定済みイベント・主体・参照原文から不足関係の候補を作ります。候補は未選択で表示され、根拠原文と理由を確認して選択したものだけを適用します。候補属性と採用理由は編集できます。入力が大きすぎる場合や図の意味情報が生成中に変わった場合は、範囲を見直して再実行してください。LLMの判断は候補であり、正しさを保証するものではありません。既存の「接続を自動修正」や「AI対策提案」とは別操作です。

SVG出力設定の「上部見出し」をオフにすると、タイトル・出力日時・件数を含む上部の帯を省き、その分だけ図を上へ詰めて出力します。オンの場合も見出しは白背景で出力されます。

ツールバーの「レーン管理」から、全レーンの表示状態（自動・表示・非表示）を変更し、空レーンを追加できます。「表示」は整理で除外されたカードも復元します。「カード整理の候補を確認」で候補を確認して適用でき、操作はUndoできます。既存の「図上では接続点として表示」とは別の設定です。非表示にしても分析対象からは除外されません。

抽出確認欄の「背景・除外・要確認の記述」には要旨と理由、対応する原文が表示されます。「この記述からイベントを再抽出」で、対応する原文と抽出済みイベントを使って再解析できます。イベント0件も明示されます。長い入力と十分な出力を扱えるモデルを使用してください。出力上限に達した応答は採用されません。

## 1. 設定（gateway.json）

クラウドLLM（OpenRouter等）とローカルLLM（LM Studio, Ollama等）を同時に設定できます。

```json
{
  "listen": { "address": "127.0.0.1", "port": 8765 },
  "security": { "client_auth": false, "credential_name": "llm_gateway|default" },
  "credentials": { "service_name": "CloudLLM", "environment_fallback": false },
  "proxy": { "max_request_body_mb": 64, "connect_timeout_sec": 10, "read_timeout_sec": 600, "write_timeout_sec": 600 },
  "model_cache": { "enabled": true, "ttl_sec": 60 },
  "cors": {
    "enabled": true,
    "allowed_origins": ["http://127.0.0.1:5173", "http://localhost:5173", "http://127.0.0.1:3000", "http://localhost:3000"],
    "allowed_methods": ["GET", "POST", "DELETE", "PUT", "PATCH", "OPTIONS"],
    "allowed_headers": ["Authorization", "Content-Type"],
    "max_age_sec": 600
  },
  "providers": {
    // ローカル PC の LM Studio
    "lmstudio": {
      "base_url": "http://127.0.0.1:1234/v1",
      "authentication": "none",
      "model_discovery": true,
      "allowlist": [{ "type": "glob", "pattern": "lmstudio/*" }]
    },
    // Tailscale 経由のリモート PC の LM Studio
    "lmstudio_remote": {
      "base_url": "http://192.0.2.1:1234/v1",
      "authentication": "none",
      "model_discovery": true,
      "allowlist": [{ "type": "glob", "pattern": "lmstudio_remote/*" }]
    },
    // ローカル PC の Ollama
    "ollama": {
      "base_url": "http://127.0.0.1:11434/v1",
      "authentication": "none",
      "model_discovery": true,
      "allowlist": [{ "type": "glob", "pattern": "ollama/*" }]
    },
    // クラウド OpenRouter (利用する場合)
    "openrouter": {
      "base_url": "https://openrouter.ai/api",
      "authentication": "bearer",
      "key_vendor": "openrouter",
      "key_slot": "default",
      "model_discovery": true,
      "allowlist": [{ "type": "glob", "pattern": "openrouter/*" }]
    }
  },
  "logging": { "level": "info", "file": "llm-gateway.log" }
}
```

## 2. 資格情報の登録（クラウドAPIを利用する場合のみ）

ローカルLLMのみ利用する場合は不要です。クラウド利用時は `llm-gateway-credential-manager.exe` または Python `keyring` で登録します。

```python
import keyring
keyring.set_password("CloudLLM", "llm_gateway|default", "gateway-token")
keyring.set_password("CloudLLM", "openrouter|default", "sk-or-v1-xxxxxx")
```

```powershell
.\llm-gateway.exe .\gateway.json
```

## 4. 疎通テスト (cURL)

### ① 利用可能モデル一覧の取得（LM Studio, Ollama, クラウド統合）
```powershell
curl.exe http://127.0.0.1:8765/v1/models
```

### ② ローカル LM Studio での推論テスト
- **ロード中モデルの直接実行**:
  ```powershell
  curl.exe http://127.0.0.1:8765/v1/chat/completions `
    -H "Content-Type: application/json" `
    -d '{"model":"lmstudio/default","messages":[{"role":"user","content":"こんにちは"}],"stream":true}'
  ```
- **指定モデルのJITロード実行**:
  ```powershell
  curl.exe http://127.0.0.1:8765/v1/chat/completions `
    -H "Content-Type: application/json" `
    -d '{"model":"lmstudio/qwen2.5-7b-instruct","messages":[{"role":"user","content":"こんにちは"}],"stream":true}'
  ```

### ③ Tailscale経由 リモート LM Studio での推論テスト
```powershell
curl.exe http://127.0.0.1:8765/v1/chat/completions `
  -H "Content-Type: application/json" `
  -d '{"model":"lmstudio_remote/default","messages":[{"role":"user","content":"こんにちは"}],"stream":true}'
```

### ④ ローカル Ollama での推論テスト
```powershell
curl.exe http://127.0.0.1:8765/v1/chat/completions `
  -H "Content-Type: application/json" `
  -d '{"model":"ollama/llama3.2","messages":[{"role":"user","content":"こんにちは"}],"stream":true}'
```

## 5. 主なエラーと対処

| Status | 内容 | 対処法 |
|:---:|---|---|
| **400** | Request・Model ID形式不正 | `provider/model` 形式（例: `lmstudio/default`）で指定してください。 |
| **401** | Client Token不一致 | `client_auth: true` の場合、認証ヘッダーを正しく付与してください。 |
| **403** | allowlist拒否 (Default Deny) | `gateway.json` の `allowlist` に `lmstudio/*` などのパターンを追加してください。 |
| **502** | 上流通信失敗 | LM Studio / Ollama が起動しているか、ポート番号やIPを確認してください。 |
| **503** | 資格情報未設定 | クラウド利用時は `llm-gateway-credential-manager.exe` でAPIキーを登録してください。 |
| **504** | 上流タイムアウト | `proxy.read_timeout_sec` を延長してください。 |

抽出は全文のテキスト変換を1回行います。形式・参照に不備があれば対象の台帳行だけを修復します。修復通信に失敗しても、同じプロジェクト・入力・モデル・プロンプトで再実行すると受信済み台帳から再開します。ページ更新やアプリ終了ではこの一時保持は消えます。原文参照は存在だけを確認するため、抽出した内容は確認欄から原文と照合してください。
# 作業依存の接続

結線等のカードが他レーンへ接続されない場合は、キャンバスの「連鎖不足をAIで点検」を使用できます。原文全文と現在の分析を照会し、不足する主体・イベント・割当・関係をTSV差分として提案します。候補は初期未選択です。原文と照合して必要な行を選び、適用後の成分数を確認して「選択した差分を一括適用」してください。新しいイベントを参照する線には、そのイベントと割当行の選択も必要です。

点検は最大2パス、対象行の修復を含め最大6回の照会です。2パス目は正常な候補を一時コピーへ取り込んで点検し、利用者の図は途中変更しません。正常行は再生成せず、不正行だけを修復します。無進展・上限・通信失敗時は正常候補を保持して停止します。処理履歴から候補IDごとの検証結果と停止理由を確認できます。応答の完了形式を確認できない場合は採用できません。割当の付替え・イベント分割は要確認とし、採用は1回のUndoで戻せます。構造がつながっても原文に忠実かを人が確認してください。

「レーン間接続をAIに提案」で、先行作業の成果物・完了・状態を必要とする後続作業への「作業依存」も提案します。原文と理由を確認して、必要な候補を選択して適用してください。矢印は前提作業から依存作業へ向き、一点鎖線で表示します。

隣接イベントを優先点検し、原文に裏付けられる工程依存は非隣接でも提案します。同一レーンの時系列線は隣接ノード間を維持します。単なる時刻の近さでは提案しません。手動で編集した線や削除した依存を自動上書きしません。

現行の生成方式は全文正規化・TSV台帳方式です。既存データの生成方式が不明な場合、部分再抽出にはこの方式を使うことを画面に表示します。


## デバッグログの記録（2026-10-29）

左側の「実行・通信ログ」にある「デバッグログを記録する」をONにしてから、イベント抽出やAI接続提案などの操作を再現してください。記録中は画面上部に「● デバッグ記録中・停止」を表示し、クリックすると停止できます。OFF後も記録済みの内容は保持します。「デバッグログを保存」でJSONファイルをダウンロードできます。「記録を消去」でメモリ内の記録を消せます。

記録対象は開始時の原文・図、LLMへのプロンプトと応答、台帳検証の不正行・採用結果、AI接続／連鎖提案の検証結果、描画へ反映された接続とbeforeとして線を描かなかった関係、プロジェクト変更時の状態です。認証ヘッダーは記録せず、設定されたGatewayトークンは通信記録から伏せます。原文・応答は含まれるため、共有時は内容を確認してください。

初期状態はOFF。記録は画面のメモリ内のみで、自動的なファイル保存・外部送信・プロジェクトへの埋込みは行いません。再読み込みで記録とON状態を破棄します。上限は500件・合計約1,000万文字、1件100万文字。超過時の古い記録の破棄／長文省略を画面と保存ファイルに示します。停止後や記録再開後に古い通信応答を詳細記録へ混入させません。通常の実行・通信ログ表示は記録OFF時も継続します。


## 主体未割当による接続不足の修復（2026-10-29）

「レーン間接続をAIに提案」では、主体未割当のため端点にできないイベントを一覧表示します。「主体・不足イベントも含めて点検」から全文連鎖点検へ進んでください。原文・全イベントを送り、不足する通常作業、主体割当、工程依存をまとめて提案します。未割当イベントも文脈に含まれますが、接続専用提案だけでは新しい割当は追加されません。

候補は初期未選択です。関係を選んだ後「選択した関係に必要な候補も選択」で、その関係が必要とするイベント・割当も選べます。原文を照合して一括適用してください。関係のsource-contextは原文全体の文脈に基づく候補です。関係の根拠区分・理由は保存・出力されます。主体割当については後述の簡素な「主体は推定」表示を使用します。

主体を特定できなければ未割当のまま保持できます。利用者自身の判断で既存主体に割り当てるか、「このイベントの仮レーンを作成」で主体未特定のレーンを明示的に追加できます。仮レーンは自動生成せず、存在する限り主体確認は未完了です。主体が判明したら名称を更新して「この主体名で確定」を押してください。機器が単なる客体である場合に、接続のためだけの機器レーンを作ることはありません。


## 正規化時の主体推定（2026-10-29 更新）

主体が文章中で省略されている場合も、イベント抽出時の全文正規化でLLMが文脈から推定してレーンへ割り当てます。推定という理由だけで後段の連鎖点検や追加確認へ回しません。推定した割当には「主体は推定」と表示し、推定根拠や原文明示との詳細区分は表示しません。確認画面・右側の説明欄・SVG説明欄・レポートで同じ表示を確認できます。

文章の直前イベントの主体をアプリが機械的に継承する処理ではありません。推定はLLMが行い、文脈からも判断できない場合だけ未割当を保持します。イベント自体が記録され、主体だけが推定なら、イベントの記録区分は変更しません。既存の図は自動再抽出しないため、この変更を使うにはイベント抽出を再実行してください。
