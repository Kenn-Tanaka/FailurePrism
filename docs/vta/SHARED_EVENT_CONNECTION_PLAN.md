# 共通イベントのレーン間接続 変更計画

2026-10-29。実装済み。自己レビューを反映。現行の保存形式は5.0。

## 1. 現状と目的

現行実装は「共通イベントIDだけでは線を作らない」規則であり、LLMが明示したtransfer/impact関係だけを生成する。そのため同じイベントの主体別カードが未接続になる。画面・SVGには矢印なしの方向種別もない。

規則を変更し、整理後に表示される同一イベントIDのカード群を必ず接続する。矢印は実際のリソース移動方向を示し、イベントの時間順や因果関係の矢印とは区別する。

## 2. 表示と意味

| 状況 | 線 | 意味 |
| --- | --- | --- |
| 人・物・資金・情報等の移動 | 一方向矢印 | 送り手・移動元から受け手・移動先 |
| 相互確認 | 双方向矢印 | 確認を行った主体間のやり取り |
| 外部事象による同時の影響 | 矢印なしの実線 | 共通イベントへの関与。主体間の影響・移動を意味しない |
| 関係や方向が判断できない | 矢印なし、「関係未判定」 | 同じイベントであることだけを表示 |
| 連絡・送付等が未実施 | 矢印なしの破線、「未実施」 | 共通の未実施イベントへの関与。実際の移動は表現しない |

添付画像の「設計変更連絡の未実施」は、カードの記述を前提に最後のケースに該当する方針とする。予定した送信元・送信先は属性として保持し、実際の情報伝達を表す矢印と混同しない。本文を含めた実際の分類はLLMまたはユーザーが行い、見出しの文字列だけでアプリが断定しない。

実施状態（実施済み・未実施・不明）と受領確認（確認済み・未確認・対象外）は別属性にする。送信自体と送信先が明記されている場合は、その方向の矢印に「受信未確認」を付けられる。通知予定だけでは送信済みの矢印を作らない。これらの状態はイベント全体で一律に決めず、主体間の関係ごとに保持する。

## 3. LLMの出力と最小限の機械処理

LLMがTSV台帳でリソースの種類、移動元・移動先、相互確認・共通影響、実施状態、原文参照を整理する。actor/targetの役割だけからアプリが移動方向を決めない。

関係表にリソース区分・実施状態を追加し、相互確認と共通影響を表す種別を用意する。同一イベント内の主体間関係では元イベントIDと先イベントIDに同じ値を指定できる。イベント間のbefore/impact等は別の意味として維持する。

アプリはイベントIDから対応カードを特定し、関係属性から線を作る。明示された関係がなくても、同じイベントの表示カードが複数なら共通イベントの無向接続を生成する。本文や見出しの類似度で同一性を推定しない。

新形式で関係の意味が未判定の場合は「関係未判定」の無向線を候補とし、ユーザーが種類・方向・実施状態を編集できるようにする。モデルに存在しないリソース移動を補わせない。「相互確認」という種別と一方向指定など、意味と方向が矛盾する組合せは確定させない。

## 4. 接続生成と表示整理

1. 原文からイベントと主体間の意味上の関係を整理する。
2. リソース移動・相互確認・共通影響・未実施の予定された関係等について、根拠のある関係の端点カードを自動整理から保護する。
3. 採用済みのカード整理・レーン表示設定を適用する。
4. 残った共通イベントのカード間に、明示関係と不足する共通イベント接続を生成する。
5. 同一レーンの隣接線を生成し、配置・描画する。

単なる重複表示の整理は従来どおり行う。自動生成した「同じイベント」という表示上の連結線の存在や既定ラベルだけでは、カードを保護しない。保護の根拠は意味上の関係、ユーザーの明示表示、手動編集・対策等とする。ユーザーが非表示カードを再表示した場合は、その時点の表示カード群に共通イベント接続を復元する。

3主体以上の場合、移動は移動元から各移動先へ接続する。相互確認は明示された主体ペアを結ぶ。共通影響や方向未判定のグループは、表示上の列順で必要最小限の無向線を使って連結する。その線は移動経路ではなく、共通イベントのまとまりを示す。意味が分からない主体ペアを双方向矢印で埋めない。

表示上の連結線にはイベントIDに対応するグループIDを持たせる。列の並べ替え・レーン非表示で描画区間が変わっても、グループの意味・注記は変えない。グループ注記はグループ単位、実際の主体間関係の編集は関係ID単位で行う。線分を編集して実際の移動方向を定義する場合は、その主体ペアの意味上の関係として記録する。

同じカードペアが複数イベントを共有する場合は、各関係に関連イベントIDを保持する。初期実装では意味上の関係を安易に一本化せず、関係IDごとに保持・描画する。同じ関係IDの二重生成だけを防ぐ。異なる関係の線が重なる場合は経路やラベルをずらす。実際の関係線で既に共通イベントのカード群が連結されていれば、同じペアに表示用の線を重ねて追加しない。未接続のカードがある場合だけ無向のグループ連結を補う。

## 5. データと画面の変更

- EdgeDirectionへundirectedを追加する。
- 共通イベントID、線の意味、リソース区分、実施状態、受領確認、自動生成／手動編集の由来を保持する。資金の区分も追加する。
- 意味上の関係には安定した関係ID、編集可能な線には安定した線IDを持たせる。TSVの関係IDも読み捨てずに保存する。関係の意味と矢印の方向は別属性とする。
- ReactFlowの表示ID、編集・削除・BREAK、対策提案の適用、保存・履歴、自動修正の照合を線IDで行う。同じsource/targetの全線を一括更新する現行処理を変更する。無向線の端点順は移動方向として解釈しない。
- VTAEdgeとSVG出力で無向線の両端マーカーを省き、「伝達」と自動表示しない。未実施の破線はBREAKによる遮断表示と区別する。
- 接続編集画面で種類・リソース・方向・実施状態を編集でき、凡例でも線の意味を説明する。
- 共通イベント内の線は全方向種別で同じ時間順位を維持する。無向線と表示用のグループ連結は、既存の時系列順位計算でも前後制約から除く。共通影響から主体間の時間差や因果関係を作らない。表示属性だけの変更でイベントの並びを変えない。
- レポートも、実際の移動・未実施・共通影響・関係未判定を区別する。新たな表示用連結線は自動のBREAK候補にしない。既存の手動BREAKおよび時系列線上のBREAKは維持し、ユーザーが指定した対策として扱う。共有イベントの無向線だけを根拠に「その線を遮断すれば被害を防げる」と生成しない。
- 保存・下書き・Undo/Redo・自動修正・SVGに属性を引き継ぐ。安定した線ID等を保存契約に追加するため形式を更新する。既定方針どおり旧形式の読込・変換は実装しない。

新形式で読み込める図や作業中の手動編集図への追加は「接続を自動修正」で候補を確認して適用する。これは旧形式プロジェクトの変換を意味しない。既存の手動線の方向・ラベル・BREAK等を維持し、1回のUndoで戻せるようにする。左右の列順変更で移動元・移動先の意味を反転させない。

自動生成・自動修正時に共通イベントの連結を保証する。ユーザーが明示的に線を削除・変更した場合は上書き情報を保持し、通常の再描画で勝手に復活させない。次の自動修正では不足・矛盾を候補として提示する。イベント・関与・関係・表示設定の各変更から同じ生成処理を利用し、生成処理の再実行だけでは重複線や新しい履歴を作らない。

## 6. 実装順序と検証

1. 線の意味・方向・実施状態とTSV台帳の契約を定義する。
2. 共通イベント接続の生成と端点保護、複数関係の識別を実装する。
3. 画面・編集・凡例・SVGを対応させる。
4. 自動修正・履歴・保存・レポート・文書を更新する。
5. 型チェック・全テスト・build.batを実行し、distと配布ZIPを更新する。

受入例は、一方向の情報・人・物・資金、相互確認、外部同時影響、未実施、方向未判定、3主体以上、同じカードペアの複数関係、接続点、列並べ替え、非表示からの復元、保存再読込・Undo/Redo・SVGとする。同一イベント内に時間差を作らないことと、表示上の線を根拠のない実際の移動・因果関係として扱わないことを確認する。

## 7. 自己レビュー結果

| 重要度 | 見つかった問題 | 計画への反映 |
| --- | --- | --- |
| 高 | 矢印の有無だけで、未実施・受信未確認・関係不明を区別できない | 関係種別、実施状態、受領確認を分離。ラベルと凡例も区別する |
| 高 | 表示用の線まで保護対象にすると、再整理で重複カードが復活し、簡素化が効かなくなる | 実関係・手動編集による保護と、自動のグループ連結を区別する |
| 高 | 現行の編集・削除はカードペアで照合するため、並行する別の関係まで変更する | 関係ID・線IDを保存し、編集・削除・BREAK等の操作をIDへ統一する |
| 高 | 同じペアの関係をまとめると、どのイベントの線を編集したか曖昧になる | 初期実装は関係ごとに保持。正確に同じIDの重複生成だけ防ぐ |
| 高 | BREAKを移動・影響だけに限定すると既存の時系列線上の対策を失う | 既存の手動対策を維持し、表示用の連結だけを自動対策の根拠にしない |
| 高 | 無向線を既存の時間順位計算へ渡すと、前後関係として扱われうる | 矢印・表示形式と時間制約を分離し、同一イベントの高さを維持する |
| 中 | 列順で無向線の描画区間が変わると、注記や編集対象が別のペアへ移る | グループIDに注記を保持し、実関係の端点・IDを列順から独立させる |
| 中 | 自動生成が手動削除や編集をすぐに元へ戻す可能性がある | 手動上書きを保持。再描画で復活させず、自動修正で差分を提示する |
| 中 | 既存図の修正対応と旧形式の変換禁止が曖昧だった | 修正対象は新形式の図と明記し、旧形式の読込・変換は対象外とする |

追加の受入確認は、同じカードペアの一方の線だけを編集・削除・BREAK指定できること、繰返し生成・整理の結果が安定すること、列並べ替えで注記を失わないこと、手動削除が再描画で復活しないこと、表示用線の追加だけで分析結果や対策の意味が変わらないこととする。

実装可能だが、VTAEdgeへ無向線を足すだけでは完了しない。線の識別・編集確定・自動整理・時間順位・分析入力を含む変更として実施する。実装後に形式・方向・保存復元・個別編集・削除の回帰テストを追加した。


## 8. 実装内容と確認範囲

共通イベント接続、移動方向・相互確認・共通影響・未実施・受信未確認の描画とSVG、線IDによる編集・削除・BREAK、グループ注記、明示削除の保持、自動修正、TSV関係表10列、保存5.0へ対応した。根拠が不明な共通イベントは無向の関係未判定線として結ぶ。必要な主体ペアの実関係だけを保護し、表示用線だけではカード整理を妨げない。

AI対策提案が端点ペアだけで複数線を指定した場合は一括適用せず、個別編集を案内する。端点だけの提案を曖昧な線へ適用しないための制限である。実LLMの抽出品質とブラウザーの手動操作は未確認。自動テストと配布用ビルドで確認する。
