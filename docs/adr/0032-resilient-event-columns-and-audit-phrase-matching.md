# ADR-0032: イベント列欠落の安全補完と監査フレーズ照合の3層防御（記号正規化・段落間補正・非停止除外）

- **ステータス**: Accepted
- **決定日**: 2026-11-10
- **対象コンポーネント**: VTA Ledger Engine (`eventLedger.ts`), Tests (`ledgerValidation.test.ts`)
- **関連要件 / ADR**: [ADR-0004](file:///docs/adr/0004-normalization-audit-and-human-traceability.md), [ADR-0016](file:///docs/adr/0016-preliminary-classification-pipeline-separation.md), [ADR-0023](file:///docs/adr/0023-ledger-prompt-disambiguation-and-preliminary-downgrade.md), [ADR-0024](file:///docs/adr/0024-ledger-parser-resilience-and-parse-error-diagnostics.md), [ADR-0030](file:///docs/adr/0030-one-sided-relation-demotion-and-ai-diagnostics-observability.md)

## 1. コンテキストと課題 (Context & Problem Statement)

東武鉄道日光線新鹿沼駅触車事故シナリオ（約7,000文字 / OpenRouter `gemini-3.8-flash`）のAI診断パッケージ（v1.0）実行において、以下の2つの軽微な形式的・表記的不整合により、高コストな台帳修復（1,686文字の指示プロンプト、8回目のLLM追加呼び出し、約30〜40秒の待ち時間増）が発生していた：

1. **イベント行の第7列（記録区分 `recorded`）省略による構文エラー**:
   ```tsv
   E1	当日朝	作業員派遣	下請会社が事前教育を受けていない作業員F、H、I、Jを派遣した	S_SUB:actor,S_HIJ:affected	p36
   ```
   LLMが末尾の `recorded` を省略して6列で出力したため、パーサーが `イベント/E1: 7列が必要です（現在6列）` としてリジェクトした。

2. **`[表現]` 監査セクションの鉤括弧剥離によるフレーズ不一致エラー**:
   ```tsv
   M5	p49	線路内に立入る場合の確認等を実施しなかった	action_only	E12	安全確認手順の未実施という客観的事実として記録
   ```
   原文 `p49` の文面は `本来実施すべき「線路内に立入る場合の確認等」を実施しなかった` であったが、LLMが抽出語句から引用符（`「` および `」`）を外して出力したため、厳格な `string.includes` が失敗し、`表現/M5: 検知語句が参照した段落に存在しません` としてリジェクトされた。

### 本質的な設計課題
- **文脈自明な省略に対する修復要求の無駄**: イベントの既定記録区分は `recorded` であり、第6列が原文参照（`p36` 等）であることが明らかな場合、第7列の欠落は決定論的に自己治癒可能である。
- **補助的監査行による本体パイプラインの停止**: `[表現]` や `[表記]` は人間による監査のための任意セクション（ADR-0004, `TEXT_LEDGER_SPEC.md`）であり、VTAグラフのノードやエッジの幾何配置・因果ネットワークには直接関与しない。このような付加的監査行の記号不一致や幻覚によって本体のダイアグラム生成を停止させ、LLM修復サイクルを強制することは過剰な硬直性であった。

## 2. 決定理由の要因・制約 (Decision Drivers)

1. **パイプライン効率と初回完走率の最大化**:
   軽微な表記揺れや末尾列省略によるLLM往復（1回あたり30〜40秒、数千トークン）を根絶し、初回パスで確定可能なデータを最大保全すること。
2. **決定論的自己治癒の厳格な境界**:
   列順がシフトした行（例: 原文参照が抜けて第6列に `recorded` が入っている行）を誤って補完せず、真に末尾区分のみが欠落した行だけを100%ピンポイントで救済すること。
3. **グラフ構造と監査記録の関心事の分離**:
   監査行の不整合が主要グラフ（主体・イベント・関係・帰結）の生成を巻き添えにしないこと（`TEXT_LEDGER_SPEC.md`「不正行は警告を記録して当該記録行のみ除外（本体は保持）」の原則遵守）。

---

## 3. 検討した選択肢 (Considered Options)

- **選択肢1: プロンプト指示の強化のみ（引用符保持・7列厳守の徹底）**
  - デメリット: LLM（特にFlash系モデルやローカルLLM）の出力トークンにおける微小な揺らぎ（Markdown記号や引用符の剥離）をプロンプトのみで100%抑制することは原理的に不可能であり、確率的な修復ループが残存する（不採用）。
- **選択肢2: 監査行のエラーを無条件に例外として扱う（従来仕様）**
  - デメリット: 監査行1件の不一致で台帳全体が未確定（`analysis: undefined`）となり、長時間の推論結果が即座に利用できない（不採用）。
- **選択肢3: ガード付きイベント補完 ＋ 監査フレーズ照合の3層防御（採用）**
  - メリット: 決定論的自己治癒と多層フォールバックにより、パイプラインの停止をゼロにしつつ、監査追跡性と警告ログの双方を完全両立する。

## 4. 決定事項 (Decision Outcome)

以下の2つの耐障害性向上メカニズムを `src/tools/vta/features/vta/utils/eventLedger.ts` に実装した：

### 1. イベント6列行の安全自動補完ガード
`inspectLedger` 内の `typed('イベント', ...)` において、列数検証の直前に以下のガード付き補完を実施：
```typescript
if (
  section === 'イベント' &&
  row.cells.length === 6 &&
  !['recorded', 'claim', 'assessment'].includes(row.cells[5])
) {
  row.cells.push('recorded');
  warnings.push(`イベント ${row.id}: 記録区分が省略されていたため、既定値 "recorded" を自動補完しました。`);
}
```
- 第6列がすでに記録区分（`recorded`/`claim`/`assessment`）である場合は、先行列の欠落（列順シフト）と判定して補完を行わず、正しく7列要求エラーとして検出する。

### 2. 監査セクション（`[表現]`・`[表記]`）の3層防御メカニズム
監査行のフレーズ照合において、以下の3層防御パイプラインを適用：
- **第1層 (Layer 1 - 記号正規化一致)**:
  `cleanPunctuation` 関数により、和文・欧文引用符（`「」『』""''“”‘’`）、括弧（`（）()【】[]〔〕《》`）、空白（スペース・タブ・改行）、句読点（`、。，．,.`）を除去した正規化文字列で照合。これにより引用符の剥離を自動吸収。
- **第2層 (Layer 2 - 原文段落間クロスサーチ)**:
  指定段落で見つからない場合、`source.paragraphs` の全段落を自動走査。他段落で一致した場合は参照段落を自動リバインドし、警告ログ（`warnings`）に補正内容を記録。
- **第3層 (Layer 3 - 非停止安全除外)**:
  原文の全段落にも存在しない架空のフレーズであった場合、例外を投げて台帳全体を停止させるのではなく、警告を記録した上で当該監査行のみを安全に除外（スキップ）。本体のダイアグラム生成は正常に完走させる。

## 5. 結果と影響 (Consequences)

### メリット
- **初回パイプライン成功率の向上**:
  東武鉄道鹿沼駅事故シナリオにおいて、2件の不整合による1,686文字の台帳修復呼び出しが完全に不要となり、推論回数が8回から7回へ削減され、レイテンシが約30〜40秒短縮される。
- **仕様との整合性**:
  `TEXT_LEDGER_SPEC.md` に明記されていた「不正行は警告を記録して当該記録行のみ除外（本体は保持）」の原則がコード上で完全に具現化された。
- **安全な自己治癒**:
  列順の狂った異常行を誤補完せず、正しく末尾列のみが欠落した行だけを安全に救済する。

### トレードオフ・考慮事項
- 第3層で除外された監査記録は結果の `normalizationAudit` には含まれないが、`warnings` 配列に除外理由と対象IDが残るため、UIの通知やログから確認可能である。
