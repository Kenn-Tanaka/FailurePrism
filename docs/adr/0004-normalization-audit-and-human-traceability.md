# ADR-0004: 正規化処理の人間による監査可能性とテキスト帳票出力機能

- **ステータス**: Accepted
- **決定日**: 2026-11-03
- **対象コンポーネント**: VTA Normalization / Audit / UI (`NormalizationAuditExportModal`)
- **関連要件**: `docs/vta/REQUIREMENTS.md` (正規化監査ログと完全追跡性)

---

## 1. コンテキストと課題 (Context & Problem Statement)

事故調査報告書やインシデント記録などの公式資料をVTAツリーに変換する際、LLMを用いた全文正規化処理（`normalizeSource`）が行われる。この処理中、LLMは以下の補正や判断を実行する：
1. **表記統一（`alias`）および明らかな誤字脱字補正（`typo`）**
2. **評価・過失認定語（「誤って」「怠った」「不注意で」等）の除去または引用供述化（`FACTUALITY_POLICY`）**
3. **分析に不要と判断された一般論の除外（`excluded`）や背景情報の分類（`background`）**
4. **イベントから一度も参照されなかった原文段落の検知**

法医学的分析や公的事故調査においては、**「AIが原文をどのように書き換えたのか、何を削り、何を解釈したのか」が完全に監査可能（Auditable）**でなければ、分析結果の正当性を証明できず、信頼性が損なわれてしまう。従来はWeb UIの折りたたみパネルで断片的に表示されるのみであり、外部提出や人間の監査官による全件精査が困難であった。

---

## 2. 決定理由の要因・制約 (Decision Drivers)

1. **完全な追跡可能性（Full Traceability）**:
   正規化前後の全差分、補正理由、検知された過失表現、未参照段落の全文を、人間が漏れなく監査できること。
2. **ポータビリティと共有性**:
   Webブラウザ上だけでなく、外部の監査記録や調査レポートの付録として容易にエクスポート・共有できるプレーンテキスト形式であること。
3. **データ安全性の保護**:
   監査テキストを出力・参照しても、既存プロジェクトのデータハッシュや検証ステータスに副作用を与えないこと。

---

## 3. 検討した選択肢 (Considered Options)

- **選択肢1: JSONデータのままエクスポートする**
  - デメリット: 技術者以外（調査官や安全管理者）にとって可読性が極めて低く、監査資料として適さない（不採用）。
- **選択肢2: 構造化テキスト帳票（Markdown / TSV）エクスポートモーダルの新設（採用）**
  - 人間が即座に読める見出し付きテキスト形式で、クリップボードコピーおよび `.txt` ダウンロードをワンクリックで提供。

---

## 4. 決定事項 (Decision Outcome)

1. **監査テキスト生成ユーティリティ (`normalizationAuditExport.ts`) の実装**:
   - 以下のセクションで構成される監査テキスト生成関数 `generateNormalizationAuditText` を作成：
     - **【ヘッダ】**: 出力日時、原文総段落数、抽出イベント数、参照段落数、未参照段落数。
     - **【第1部 表記の統一・誤字脱字補正の記録】**: 原文表記、統一後表記、該当段落ID、補正理由。
     - **【第2部 主観表現・評価過失語の検知と処理記録】**: 検知語句、処理区分（語句除去／供述引用化／行為のみ記録）、対象イベントID、理由。
     - **【第3部 全文走査における未参照段落の記録】**: どのイベントからも参照されなかった原文段落のIDと本文全文（情報の脱落がないかを監査官が検証可能）。
     - **【第4部 整理・背景・除外された記述の記録】**: VTAカードにならなかった背景情報や除外記述の要旨と理由。
2. **監査テキスト出力モーダル (`NormalizationAuditExportModal.tsx`) の配置**:
   - イベント確認画面（`EventReviewPanel`）の上部に「正規化監査テキスト出力」ボタンを配置。
   - モーダル内で全文プレビュー、行数・文字数確認、クリップボードコピー、`.txt` ファイルダウンロードを提供。

---

## 5. 結果と影響 (Consequences)

- **メリット**:
  - LLMが介入したすべての判断（表記変更、過失語除去、未参照部分）が完全に可視化され、事故調査における監査基準・説明責任をクリアした。
  - 監査官やレビューアーが原文とVTAツリーの照合を極めて短時間で客観的に行えるようになった。
- **影響ファイル**:
  - `src/tools/vta/features/vta/utils/normalizationAuditExport.ts`
  - `src/tools/vta/features/vta/components/NormalizationAuditExportModal.tsx`
  - `src/tools/vta/components/control-panel/EventReviewPanel.tsx`
  - `tests/vta/normalizationAuditExport.test.ts`
