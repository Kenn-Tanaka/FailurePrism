# ADR-0001: 2段階イベント分類（正規化時仮判定）と仮判定一括採用・一括Undo

- **ステータス**: Accepted
- **決定日**: 2026-11-04
- **対象コンポーネント**: VTA Pipeline / LLM Services / UI (`EventReviewPanel`, `ScenarioInputSection`)
- **関連要件**: `docs/vta/REQUIREMENTS.md` (仮変動判定と確定判定の分離)

---

## 1. コンテキストと課題 (Context & Problem Statement)

VTA（Variation Tree Analysis: 変動樹解析）の分析原則では、「客観的事実の把握（誰が・いつ・何をしたか）」と「変動・逸脱の評価（何が標準から外れていたか）」を混同しないことが極めて重要である。

もし自動生成の初期段階（全文正規化時）でAIが変動要因まで勝手に確定してしまうと、AIによる過失認定やバイアス（「誤認」「不注意」等の主観的評価）がツリーの骨格に刷り込まれ、客観的証拠に基づかない予断を招く重大なリスクがある（`FACTUALITY_POLICY`）。

そのためシステムは生成完了時点ではイベント種別を `unclassified`（未確定）とし、各イベントに対しては参考情報として `event.preliminary`（仮判定）を保持する設計としていた。しかし、事故調査報告書のような長文資料ではイベント数が数十件に及び、イベント確認画面で1件ずつ「仮判定を採用」をクリックする作業はアナリストに大きな負担を強いていた。

また、アナリストからは「テキスト一覧表（TSV）よりも、スイムレーン・因果連鎖・帰結へのパスが空間的に可視化されたVTA図面上で仮設の変動要因を確認し、不要な設定は手動で変更したい」という強い実務要請があった。

---

## 2. 決定理由の要因・制約 (Decision Drivers)

1. **事実性原則（`FACTUALITY_POLICY`）の堅持**:
   AIによる予断の無断固定化を防ぎ、人間が意図して採用・監査する権限を確保すること。
2. **作業効率の最大化**:
   数十件におよぶイベントの仮判定を1クリックで図面に流し込めること。
3. **完全な可逆性（一括Undo）**:
   図面上で仮判定を確認した結果、意図と異なる場合は1ステップで完全に元（未判定状態）に戻せること。
4. **柔軟な適用範囲（代案A）**:
   「変動要因カードのみを際立たせたい場合」と「ツリー全体（通常＋変動）を完成形として俯瞰したい場合」の双方に対応できること。
5. **アクセス容易性（代案B）**:
   確認パネルを開く手間なく、メイン操作パネル（サイドバー）からも直接ワンクリックで図面へ適用できること。

---

## 3. 検討した選択肢 (Considered Options)

- **選択肢1: 全文正規化時にAIが変動要因を自動確定する**
  - メリット: ワンステップで色分けされたツリーが完成する。
  - デメリット: `FACTUALITY_POLICY` に反し、AIの誤認や過失認定が固定化されるリスクが極めて高い（不採用）。
- **選択肢2: 確認パネル内での1件ずつの手動採用のみを継続**
  - メリット: 最も慎重。
  - デメリット: 大規模事例での操作コストが高すぎて実用に耐えない（不採用）。
- **選択肢3: 代案A＋代案B（採用）**
  - コア関数 `batchAdoptPreliminary` を新設し、二層モード（`variation_only` / `all`）と手動変更保護を提供。
  - 確認パネル内（`EventReviewPanel`）に即時Undo付きの一括採用ボタンを設置。
  - メイン操作パネル（`ScenarioInputSection`）にも直接図面へ反映する一括採用ボタンを設置し、`vtaStore.undo`（Ctrl+Z）による1ステップ完全復元を保証。

---

## 4. 決定事項 (Decision Outcome)

1. **2段階アーキテクチャの確立**:
   - **第1段階（全文正規化・反復最適化）**:
     LLMは `[仮判定]` セクションで各イベントに `normal` / `variation` / `undetermined` の仮説を立案し `event.preliminary` に記録するが、正式種別は `unclassified` を維持する。
   - **第2段階（一括採用または本判定）**:
     ユーザーの明示的トリガーにより、仮判定を一括採用（0秒）するか、LLMによる正式4分類・SRK行動レベル・レジリエンス極性の本判定（`handleClassify`）を実行する。
2. **`batchAdoptPreliminary` 関数の共通化**:
   - `mode: 'variation_only'`: 未判定かつ仮判定が `variation` のもののみ昇格。
   - `mode: 'all'`: 未判定かつ仮判定が `variation` または `normal` のものをすべて昇格。
   - `classification !== 'unclassified'` の手動判定済みイベントは上書きせず保護。
3. **二重のUndo機構の提供**:
   - **パネル内即時Undo**: 確認パネル内で `preBatchAnalysis` スナップショットを保持し、「↩ 一括採用を取り消す」で即座に直前の状態へ復元。
   - **キャンバス1ステップUndo**: メインパネルまたは確認パネルからキャンバスへコミットされた変更は1つの履歴スナップショットとして記録され、`Ctrl+Z`（またはツールバーの「元に戻す」）で丸ごと未判定状態へ復元。

---

## 5. 結果と影響 (Consequences)

- **メリット**:
  - 事実性・中立性を損なうことなく、長大事故シナリオの分析作業時間が劇的に短縮された。
  - VTA図面の視覚的・空間的文脈（レーン・エッジ・帰結パス）の中で変動要因の妥当性を迅速に検証可能になった。
  - 試行錯誤のコストがゼロになり、誤って適用しても即座に元の状態へ戻せる安全性が確保された。
- **影響ファイル**:
  - `src/tools/vta/features/vta/utils/eventAnalysis.ts`
  - `src/tools/vta/components/control-panel/EventReviewPanel.tsx`
  - `src/tools/vta/components/control-panel/ScenarioInputSection.tsx`
  - `tests/vta/batchAdoptPreliminary.test.tsx`
