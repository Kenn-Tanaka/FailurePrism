# ADR-0013: 機器主体のレーン化抑制・組織包含の抽出義務付けおよび粒度反復における原文コンテキストスライシング

- **ステータス**: Accepted
- **決定日**: 2026-11-06
- **対象コンポーネント**: VTA Subject Ranking, Refinement Prompt Engine, LLM Prompts, Subject Poset
- **関連ドキュメント・コミット**: [ADR-0008](file:///docs/adr/0008-subject-outcome-sharing-and-non-influential-exclusion-policy.md), [ADR-0010](file:///docs/adr/0010-subject-poset-dag-and-canonical-inclusion.md), [ADR-0011](file:///docs/adr/0011-olap-drilldown-and-rollup-for-subject-poset.md)

---

## 1. コンテキストと課題 (Context & Problem Statement)

羽田空港C滑走路衝突事故の調査報告書（約28,500文字・206イベント）の実機データ検証において、以下の致命的な品質・通信問題が確認された。

1. **上位組織の欠落と包括エッジの全滅 (`edge_count: 0`)**:
   - LLM（Gemini 3.8 Flash）が `[主体]` セクションを出力する際、上位組織（海上保安庁、日本航空、東京空港事務所／管制機関）を抽出せず、個人主体（機長A、機上通信員A、訓練乗員B、各管制官）のみをバラバラに抽出し、所属・上位主体にすべて `-` を出力した。
   - この結果、`SubjectPoset` のエッジ数が0となり、階層集約やドリルダウンが機能せず完全にフラットな孤立20主体となった。
2. **機器（システム支援機能）による上位レーン占有と重要アクターの埋没**:
   - 「滑走路占有監視支援機能」が主体（machine）として抽出され、複数イベントへの関与や「未検知」等の不作為キーワードに該当した結果、スコアリング上位枠を奪取した。
   - 親組織がないため、あふれたタワー管制官・グラウンド管制官等の最重要アクターがすべて「その他の関係者（`subject_others`）」へ押し込められ、本来の管制対航空機の相互作用が完全に隠蔽されたVTA図となった。
3. **粒度反復レビューにおける HTTP 504 (upstream_timeout) 通信失敗**:
   - `granularityRefinement` において、28,500文字の原文全段落がそのままプロンプトへ埋め込まれた結果、OpenRouter Gatewayの読み込みタイムアウト（約36秒）を超過し、初期スコア $S=0.523$ という極めて粗い状態から一切反復改善されずに打ち切られた。

## 2. 決定理由の要因・制約 (Decision Drivers)

- **VTAの本質（ヒューマンファクタ・組織分析）**:
  - VTAは人間および組織の意思決定・協調行動を分析する手法であり、監視支援機能や警報装置等の機器は、それを運用・監視する組織／人間の客体またはサブレーンとして位置付けられるべきである。生身の人間や組織を押し出してメインレーンを占有することは許容されない。
- **組織包含（Poset DAG）の確実な構築**:
  - 個人が登場する場合、必ずそれを束ねる上位組織を定義させ、包括階層（`edge_count > 0`）を構築しなければ、多層集約・ドリルダウン（ADR-0010, ADR-0011）が破綻する。
- **長大ドキュメントにおける通信安定性（Gateway Timeout 撲滅）**:
  - 報告書全文（数万文字）を反復レビューごとに往復させることはレイテンシとゲートウェイタイムアウトの元凶であり、因果シナリオや参照段落に基づく安全なスライシングが不可欠である。

---

## 3. 検討した選択肢 (Considered Options)

- **選択肢A (LLMプロンプトの指示強化のみ)**:
  - プロンプトで「機器をレーンにするな」「組織を必ず抽出せよ」と強調する。
  - *評価*: 小規模モデルやプロバイダのゆらぎによって指示が漏れた場合、決定論的パイプラインで再度機器がレーンを奪うリスクが残る。
- **選択肢B (決定論的パイプライン＋プロンプトの二重防護アーキテクチャ - 採用)**:
  - プロンプト側で上位組織の抽出義務付けおよび支援ツールの客体化原則を明記。
  - 決定論的パイプライン（`subjectRanking.ts`）で、`organization` / `person` を最優先し、`machine` のメインレーン選出を抑制（不作為パターンの除外と種別優先度 `kindWeight` の導入）。
  - さらに `granularityRefinement.ts` において、長大原文をイベント根拠段落優先で安全にスライシング（上限15,000文字）して 504 タイムアウトを根本遮断する。

---

## 4. 決定事項 (Decision Outcome)

### 4.1 主体ランキングにおける機器（machine）のレーン化抑制
1. **不作為パターンの機械除外 (`isInfluentialSubject`)**:
   - システム支援機能の未検知・不作動を理由に人間や組織より優先して `influential: true` 昇格させないようガード。
2. **種別優先度ソート (`rankSubjects`)**:
   - candidate ソート時に `kindWeight`（`organization` / `person`: 2, `other`: 1, `machine`: 0）を適用。
   - 同等の影響度・スコアであっても、生身の人間や組織が優先的に上位レーン枠を獲得し、機器が人間を「その他」へ押し出すことを決定論的に防止。

### 4.2 粒度反復における長大原文のコンテキストスライシング
1. **`sliceRelevantSourceParagraphs` の導入**:
   - 原文が15,000文字を超える長大シナリオの場合、全段落の盲目的埋め込みを廃止。
   - 冒頭概要段落（最初の3段落）および、イベント・帰結が直接参照している根拠段落（direct）を優先抽出してスライス。
   - OpenRouter Gateway の 36秒制限（HTTP 504）を完全に回避し、反復レビューの完遂を保証。

### 4.3 プロンプト規約の改訂 (`SUBJECT_FOCUS_POLICY`, `SUBJECT_LANE_POLICY`)
1. **上位組織の抽出義務付け**:
   - 個人（機長、操縦士、管制官、作業員等）を抽出する場合、必ずそれらを包摂する上位組織（海上保安庁、日本航空、東京空港事務所等）も同時に[主体]に登録し、個人の「所属・上位主体」列に指定することを義務付け。
2. **支援ツールの客体化原則**:
   - 支援機能・警報画面・センサー等は、運用・監視主体の客体として扱うことを原則とし、人間や組織の主レーンを奪ってまで独立レーン化しないことを明記。

---

## 5. 結果と影響 (Consequences)

### メリット
- 長大インシデント（羽田事故など）において、機器が独立レーンを占有し管制官が埋没する不自然な図面生成を決定論的に撲滅。
- 粒度反復レビューの Gateway Timeout（HTTP 504）が解消され、局所最適脱出と接続改善が確実に完遂。
- 組織包含階層（Poset DAG）が確実に形成され、ドリルダウン・ロールアップ機能が本来の威力を発揮。

### トレードオフ・考慮事項
- 万が一、完全に自律動作するAIエージェント等の機器主体を最重要レーンに据えたい場合は、ユーザーが「固定主体（pinnedEntityIds）」または「focus: high」で明示的に指定可能。
