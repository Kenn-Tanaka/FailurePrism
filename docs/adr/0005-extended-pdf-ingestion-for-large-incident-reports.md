# ADR-0005: 長大事故調査報告書（250ページ対応）のPDF読み込み制限拡張

- **ステータス**: Accepted
- **決定日**: 2026-11-03
- **対象コンポーネント**: VTA File Ingestion / PDF Parser / Memory Management
- **関連要件**: `docs/vta/REQUIREMENTS.md` (ファイルインジェスト制限)

---

## 1. コンテキストと課題 (Context & Problem Statement)

重大インシデント（例: 2024年12月に公表された羽田空港航空機衝突事故の経過報告書は158ページ）のような本格的な公式調査報告書は、100〜200ページを超える長大なPDF資料であることが一般的である。

従来のVTAエディタでは、ブラウザのフリーズ防止やリソース制限のため、PDF読み込み上限が低め（50〜100ページ程度）に制限されていた。その結果：
- ユーザーは外部のLLMやツールを用いて手作業でテキストを抽出し、要約や分割を行ってからVTAエディタに流し込まざるを得なかった。
- 事前要約や手動テキスト抽出により、原文のページ・段落番号情報が欠損し、VTAの根拠参照（`p1, p2...`）の精度が著しく低下する懸念があった。
- 一方、長大なPDFであっても「一度読み込んでプロジェクト（`.json`）として保存すれば、次回以降は瞬時に開ける」ため、初回の読み込み時に250ページ程度まで直接読み込めることが強く求められた。

---

## 2. 決定理由の要因・制約 (Decision Drivers)

1. **実務での無加工読み込み**:
   公表された一次資料PDFを分割や要約なしにそのままドラッグ＆ドロップして読み込めること。
2. **ブラウザの安定性とメモリ制限の遵守**:
   PDF.jsを用いたブラウザ内クライアント処理において、メモリ枯渇（OOM）やUIスレッドの長時間ロックを防止すること。
3. **安全上限とエラーハンドリング**:
   上限（250ページ / 25MB）を超過したファイルが投入された際、異常終了せず分かりやすい警告とガイダンスを表示すること。

---

## 3. 検討した選択肢 (Considered Options)

- **選択肢1: ページ数制限を完全撤廃する**
  - デメリット: 1000ページ超の資料が投入された際にブラウザクラッシュを引き起こすリスクがある（不採用）。
- **選択肢2: サーバーサイドでPDF解析を行う**
  - デメリット: ローカル完結型（ローカルLLM Gateway＋クライアント処理）のプライバシー保護・エアギャップ環境運用の前提を崩してしまう（不採用）。
- **選択肢3: クライアント内PDF.js抽出の上限を250ページへ安全に拡張する（採用）**
  - ファイルサイズ上限（25MB）を維持しつつ、PDFのページ抽出ループの上限を250ページに引き上げ、超過時の安全ガードと警告を整備。

---

## 4. 決定事項 (Decision Outcome)

[`src/tools/vta/features/vta/utils/fileIngestion.ts`](file:///c:/Users/kenta/Dropbox/2026年/ソフトウェア開発/2026-10-17_FailurePrism/src/tools/vta/features/vta/utils/fileIngestion.ts) において、以下の定数およびバリデーションを改修した：

1. **ページ上限の更新**:
   - `MAX_PDF_PAGES = 250`（旧上限から250ページへ拡張）。
   - ファイルサイズ上限 `MAX_FILE_BYTES = 25 * 1024 * 1024` (25MB) は継続。
2. **ページ超過時の明示的エラーメッセージ**:
   - 250ページを超えるPDFが指定された場合、`「PDFのページ数が上限（250ページ）を超えています（該当ファイル: Nページ）。」` と詳細なページ数を明示し、ユーザーに分割や範囲指定を促す。
3. **段落分割とメモリ効率**:
   - 抽出された各ページ内のテキストを行・段落単位で正規化し、無駄なオブジェクト生成を抑えて段落リストを構築。

---

## 5. 結果と影響 (Consequences)

- **メリット**:
  - 羽田空港事故（158ページ）をはじめとする国内・国際的な公式事故調査報告書を、原文PDFのまま直接インジェスト可能になった。
  - 原文のページ・段落情報がそのまま証拠参照（`sourceRefs`）として保持されるため、監査性と引用精度が飛躍的に向上した。
- **影響ファイル**:
  - `src/tools/vta/features/vta/utils/fileIngestion.ts`
  - `tests/vta/fileIngestionLimits.test.ts`
